1. ROS2とは何か。

ROS2 は、Robot Operating System 2 の略です。名前に反して、OS、つまりオペレーティングシステムではありません。ロボット向けのソフトウェアを作るための、通信の仕組み、ビルドツール、標準ライブラリ、開発ツールの集まりです。

ロボットのソフトウェアでは、複数のプログラム、つまりノードが、センサの値や制御の指令などのデータをやり取りしながら、協調して動きます。ROS2 は、こうしたソフトウェアに共通する土台を、車輪の再発明をせずに使えるようにします。

ROS2 は、初代の ROS、つまり ROS1 を作り直したものです。ROS1 の最後の版のサポートは、2025年5月に終わりました。ROS1 との違いは、今から ROS2 で始める分には知らなくても困らないので、Tips集の7節にまとめてあります。ROS1 で書かれた古いコードを ROS2 へ移す方法と注意点も、同じ節にあります。

2. 通信の仕組みの概要: 層を積み重ねた構造。

ROS2 でノードどうしがデータをやり取りするとき、自分が書くコードが、直接ネットワークを操作しているわけではありません。間には役割の違う層がいくつも積み重なっていて、上の層は、すぐ下の層に「これを送って」と頼むだけで済みます。このように、通信の仕事を層に分けて積み重ねた構造を、プロトコルスタックと呼びます。Web のページを見るときに、ブラウザの HTTP の下で TCP が、その下で IP が働いているのと同じ考え方です。

原文では、この構造を図にしています。同じ内容の図が2つあり、1つは画像の SVG、もう1つは mermaid という記法で書いた図です。ここでは、その図の中身を言葉で説明します。

図の中央には、5つの箱が、上から下へ1列に並び、矢印でつながっています。

一番上の箱は「ノード」で、自分が書くコードです。Python なら rclpy、C++ なら rclcpp を使います。

2つ目の箱は「ROS クライアントライブラリ」、略して RCL です。publisher や subscription などの API を提供します。

3つ目の箱は「RMW」、ROS Middleware Interface です。DDS の実装を差し替えられるようにする、抽象の層です。

4つ目の箱は「DDS の実装」で、ミドルウェアの本体です。例として Fast DDS や Cyclone DDS が挙げられています。

一番下の箱は「ネットワーク」です。通常は UDP とマルチキャストで通信します。

この列の右側には、点線の枠の注記が2つあり、それぞれ点線の矢印でつながっています。1つは RMW の箱の横にあり、「環境変数 RMW_IMPLEMENTATION で、DDS の実装を切り替えられる」と書かれています。もう1つはネットワークの箱の横にあり、「まとめ役の中央のサーバは無い。互いに自動で見つけ合う」と書かれています。

図の層の名前、RCL、RMW、DDS は、今は覚えなくてよい、と原文は言います。押さえておきたいのは、層に分かれていることで得られる、次の3つです。

1つ目。書く人は、一番上だけを見ればよい。ノードを書くときに使うのは、一番上の rclpy や rclcpp の API だけです。データがどんな形でネットワークを流れるかは、下の層が引き受けます。
