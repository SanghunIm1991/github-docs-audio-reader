NVIDIA のフィジカルAI開発技術。

これは、NVIDIA が提供している、フィジカルAIの開発の技術についての話です。

NVIDIA は、フィジカルAIの開発に使う計算機、ソフトウェア、モデル、データを、まとめて提供しています。原文のファイルでは、その全体の構成と、主な技術を整理しています。1つの企業の技術を集めたテーマなので、性能や使いやすさの評価は載せず、何を提供しているかを、開発元の一次情報から整理しています。開発元の主張は、「開発元によれば」として書いています。

選び方と、このファイルの範囲。

選び方はこうです。開発元が示す構成、つまり後で説明する「3つの計算機」の各部分から、ロボットと自動運転の開発に直接かかわるものを選びました。同じ目的のものは、1つの項目にまとめています。例えば、Alpamayo の 1 と 1.5、GR00T-Mimic と GR00T-Dreams です。

ほかのファイルに載せているものもあります。次の技術は、それぞれのテーマのファイルに項目があるので、このファイルでは項目にせず、後の表で位置づけだけを示しています。

1つ目。VLM や世界モデルとして使える基盤モデルの Cosmos 3 と、人型ロボットなどに向けた VLA の Isaac GR00T。これらは VLM のファイルにあります。

2つ目。シミュレータと学習の枠組みの Isaac Sim と Isaac Lab、そして物理エンジンの Newton。これらはシミュレータのファイルにあります。Newton は、NVIDIA が Google DeepMind、Disney Research とともに始め、現在は Linux Foundation のプロジェクトです。

今回は載せていないものもあります。学習用の計算機である DGX そのもの。センサーのデータを処理する基盤の Holoscan。これは Jetson Thor の項目で、そこで動かすソフトウェアとして触れるだけにしています。工場や都市の映像解析向けの基盤の Metropolis。そして、自動運転の車載の計算機と、認証のための基盤の DRIVE です。どれも、フィジカルAIの開発の入口からは一段遠いと判断した、としています。

3つの計算機と各技術の位置づけ。

開発元は、フィジカルAIの開発を、3種類の計算機の役割に分けて説明しています。原文では、これを3行の表にまとめています。表の列は、役割、計算機、そして元のリポジトリで扱う技術、の3つです。

1行目の役割は、学習です。基盤モデルの事前学習や、ロボットの方策の追加学習がこれにあたります。計算機は DGX です。扱う技術は、Cosmos 3、Isaac GR00T、Alpamayo です。

2行目の役割は、シミュレーションと、学習用データの生成です。計算機は、Omniverse と Cosmos を動かすサーバーで、名前は RTX PRO Server です。扱う技術は7つあります。Omniverse と OpenUSD、PhysX、Isaac Sim と Isaac Lab、Newton、AlpaSim、Isaac GR00T のデータ生成の設計図、そして Physical AI データセットです。

3行目の役割は、ロボットの上での実行です。計算機は Jetson Thor です。扱う技術は、Jetson Thor そのものと、Isaac ROS です。

原文は、この表に3つの補足を付けています。

1つ目は、人型ロボットの場合の流れの例です。これは、各項目の一次情報をもとに、元のリポジトリがまとめたものです。データの生成の部分は、GR00T-Mimic についての開発元の解説によります。流れは4段です。まず、人の操作の記録を、GR00T-Mimic で数を増やし、Cosmos で見た目を多様にします。次に、そのデータで、Isaac Lab で方策を学習させるか、Isaac GR00T を追加学習します。その次に、Isaac Sim で試します。最後に、Jetson Thor の上で、Isaac ROS などと組み合わせて動かします。

2つ目は、NVIDIA の技術で閉じているわけではない、という点です。例えば、Isaac GR00T の追加学習のデータは、Hugging Face のロボット学習の枠組みである LeRobot の形式を拡張したものを使います。これは、Isaac GR00T の公式リポジトリの README の表記によります。また、Isaac ROS は ROS 2 の上で動きます。一方で、GPU で計算する部分の多くは、NVIDIA の GPU を前提にしています。

3つ目は、ライセンスが技術ごとに違う、という点です。コードは Apache-2.0 などのオープンソースのライセンスが多いです。一方、モデルの重みとデータには、NVIDIA の独自の条件のものや、OpenMDW-1.1 のものがあります。独自の条件の例は、NVIDIA Open Model License や、NVIDIA の自動運転のデータセットの利用許諾です。使う前に、各項目の一次情報で確かめてください。

全体像: 3つの計算機の構成。

これは、NVIDIA が、ロボットの開発に要る計算機を、3つの役割で説明した記事です。2024年10月に公開され、2025年8月に更新されました。

3つの計算機は、次のとおりです。1つ目は、モデルを学習させる DGX。2つ目は、仮想の環境での試験と、学習用データの生成を受け持つ、Omniverse と Cosmos を動かすサーバー、RTX PRO Server。3つ目は、ロボットの上で、センサーのデータを処理し、モデルを動かす Jetson AGX Thor です。

各部分で使うソフトウェアとして、Cosmos、Isaac GR00T、Isaac Sim、Isaac Lab、そして工場のデジタルツインの設計図である Mega を挙げています。

NVIDIA の製品の紹介を兼ねた記事なので、原文では、構成の考え方をつかむために読むもの、としています。一次情報は、開発元のブログです。

モデル: Alpamayo。

Alpamayo は、NVIDIA の、自動運転に向けた VLA です。パラメータ数は 10B です。

車のカメラの映像から、2つのものをあわせて出力します。1つは、走る軌跡で、先の6.4秒分です。もう1つは、その判断の理由を言葉で説明した、推論の過程です。土台には、NVIDIA の推論型の VLM である Cosmos-Reason を使います。

2026年3月に出た Alpamayo 1.5 は、4つのことに対応しました。強化学習での追加の学習、道案内の指示の入力、カメラの台数の変更、そして映像についての質問への回答です。追加の学習、つまり教師ありの学習と強化学習の手順は、Alpamayo Recipes という別のリポジトリで公開しています。

最初の版の Alpamayo 1 は、旧名が Alpamayo-R1 です。そのリポジトリは保守だけの段階に入り、1.5 を勧めています。

ライセンスは、README の表記によれば、コードが Apache-2.0、モデルの重みが OpenMDW-1.1 です。ただし、商用での利用についての表記がそろっていません。リポジトリの FAQ は、「ライセンスとモデルの説明に従って可能」としています。一方、モデルの公開ページは、「非商用の利用に向けた準備ができている。商用の許諾は要望に応じる」としています。

状態は研究段階です。README の注意書きで、研究、実験、評価に向けたものとし、自動運転の仕組みの全体ではなく、車載の品質の検証もしていない、としているためです。

一次情報は、Alpamayo 1.5 と Alpamayo 1 の公式リポジトリ、Alpamayo 1 の論文、そして Alpamayo 1.5 のモデルの公開ページです。

シミュレーションとデータ: Omniverse と OpenUSD。

Omniverse は、フィジカルAIのための仮想の空間を作るための、NVIDIA のライブラリ、道具、設計図の集まりです。ここでいう仮想の空間とは、シミュレーションにそのまま使える 3D の世界のことです。

3D の場面の共通の形式である OpenUSD を土台にしています。そのうえで、次のような道具をそろえています。物理の計算の PhysX と Newton。GPU での描画と、センサーの模擬。実世界のデータから場面を再構成する NuRec。URDF や MuJoCo などの形式からの変換。

開発元は近年、Omniverse を、人だけでなく AI のエージェントが呼び出して使う道具としても位置づけています。

設計図、つまり参照用の作業の流れとして、複数のロボットが働く工場のデジタルツインの Mega や、ロボットの操作の学習用データを生成する GR00T-Mimic などを用意しています。なお、Isaac Sim は、Omniverse の上で動くアプリケーションです。

ライセンスは部品ごとに違います。開発元のページは、一部の道具をオープンソースとしています。例えば、PhysX は BSD-3-Clause です。

状態は実用です。開発元が製品として提供しているためです。一次情報は、開発元の Omniverse のページです。

シミュレーションとデータ: PhysX。

PhysX は、NVIDIA の物理エンジンで、リアルタイムの計算を目的としています。Omniverse の物理の計算の部分、つまり Omniverse PhysX の拡張として使われ、Isaac Sim もその上で動きます。

リポジトリには、本体のほかに、3つのものが入っています。OpenUSD で書いた場面の物理を Python から計算する窓口の ovphysx。物の破壊を扱う Blast。流体や炎を扱う Flow です。開発元は、Omniverse、PhysX、Isaac Sim の版の対応を、表で示しています。

ライセンスは BSD-3-Clause です。

状態は実用です。正式な版の公開が続いていて、確認した時点で、本体の SDK は 5.12.0 までの版が示されています。一次情報は、公式リポジトリです。

シミュレーションとデータ: AlpaSim。

AlpaSim は、NVIDIA の、自動運転の方策を試すためのシミュレータです。ここでいう方策は、運転の判断をするモデルのことです。方策の出力に応じて場面が変わる、「閉ループ」の試験を行います。

構成は、描画、交通、車の動き、制御を、別々のプロセスに分け、gRPC でつなぐ形です。そのため、部品を差し替えたり、複数の GPU や計算機に分けて動かしたりできます。

描画は、実際の走行のデータから再構成した場面、つまり NuRec を既定としていて、動画を生成するモデルによる描画にも対応します。README によれば、Alpamayo のほか、他の開発元の運転の方策である VaVAM や Transfuser にも対応します。

ライセンスは、コードが Apache-2.0 です。場面のデータは、後で説明する Physical AI データセットの条件によります。

状態は研究段階です。README で研究と開発のためのものとしていて、正式な版の番号も示されていないためです。一次情報は、公式リポジトリです。

シミュレーションとデータ: Isaac GR00T のデータ生成の設計図。

これは、人型ロボットなどの学習用データを人工的に増やすための、NVIDIA の2つの参照用の作業の流れです。

1つ目は GR00T-Mimic です。2025年1月に初めて出ました。少数の人の操作の記録を、Isaac Lab で多数の動きの軌跡に増やし、背景や照明を変えたうえで、Cosmos で見た目を写実的にします。今ある作業を得意にさせるためのものです。

2つ目は GR00T-Dreams です。論文は2025年5月で、論文での名前は DreamGen です。1枚の画像と言葉の指示から、世界モデルの Cosmos Predict で、ロボットが新しい作業をする動画を作ります。そして、その動画から動作を推定して、学習用データにします。新しい作業や環境に広げるためのものです。開発元によれば、GR00T-Dreams で作ったデータを使って、Isaac GR00T N1.5 を36時間で開発しました。

ライセンスは、GR00T-Dreams が Apache-2.0 です。GR00T-Mimic のリポジトリは、それ自体のライセンスを示さず、使う部品である Isaac Sim、Isaac Lab、Cosmos のモデルの条件を挙げています。

状態は研究段階です。どちらも参照用の作業の流れで、正式な版の番号は示されていないためです。また、GR00T-Mimic のリポジトリは、Isaac Sim 4.5.0 と Isaac Lab 2.0.2 を使う時期のものです。シミュレータのファイルに載せた Isaac Sim の最新の版、つまり2026年10月17日に確認した 6.2.0 より古い、と原文は注意しています。

一次情報は、GR00T-Mimic と GR00T-Dreams の、それぞれの公式リポジトリと開発元の解説、そして DreamGen の論文です。

シミュレーションとデータ: Physical AI データセット。

これは、NVIDIA が Hugging Face で公開している、フィジカルAIの開発のためのデータセットの集まりです。開発元は、「商用に使える品質のオープンなデータセット」としています。

含まれるものには、次のようなものがあります。

1つ目は自動運転です。25か国、2,500以上の都市で集めた、約1,700時間の走行のデータで、カメラ7台の映像、LiDAR、レーダーを含みます。

2つ目はロボットの操作です。Isaac GR00T の追加学習用の、シミュレーションと人の操作の記録の軌跡などです。

3つ目は、倉庫などの場面。4つ目は、世界モデル用の人工的な場面です。

各データセットの説明によれば、自動運転のデータセットは Alpamayo に、ロボットの操作の例のデータセットは Isaac GR00T の追加学習に使われています。

ライセンスは、データセットごとに違います。例えば、自動運転のデータセットは、NVIDIA の独自の利用許諾です。利用の申し込みが要り、用途を自動運転と運転支援の社内の開発に限り、再配布を禁じ、期限は取得から12か月です。一方、Isaac GR00T の追加学習用の例は、CC BY 4.0 です。

状態は実用です。版を重ねて公開されていて、自動運転のデータセットは、確認した時点で 26.09 が最新です。

一次情報は、データセットの集まりのページ、自動運転のデータセット、Isaac GR00T の追加学習用のデータセットの例です。

ロボットのソフトウェアと計算機: Isaac ROS。

Isaac ROS は、ROS 2 でロボットを作るための、NVIDIA の GPU で速く動くパッケージの集まりです。

主に次のものを含みます。

カメラによる自己位置の推定と地図づくりの、Visual SLAM。

3D の地図と障害物の把握の、nvblox。

ステレオカメラからの深度の推定の、FoundationStereo。

初めて見る物の、位置と姿勢の推定の、FoundationPose。

腕の動きの計画の、cuMotion。これは MoveIt の拡張として使えます。

そして、ROS 2 のデータの受け渡しを速くする仕組みの、NITROS です。

Isaac Sim での試験から、Jetson の上での実行までを想定していて、腕の操作と移動ロボットの、参照用の作業の流れも用意しています。

ライセンスは Apache-2.0 です。これは、公式の GitHub の組織で確かめた主なリポジトリの表記で、パッケージごとに確かめるように、と原文は注意しています。

状態は実用です。正式な版の公開が続いていて、確認した時点の最新は、2026年9月21日の 5.0.0 です。対応する ROS 2 の版は Lyrical Luth です。

一次情報は、開発元の Isaac ROS のページ、公式の GitHub の組織、リリースノートです。

ロボットのソフトウェアと計算機: Jetson Thor。

Jetson Thor は、ロボットに載せて AI を動かすための、NVIDIA の小型の計算機です。Blackwell 世代の GPU を使います。

部品は2種類あります。上位の T5000 は、メモリが 128 GB、消費電力が 40 から 130 W です。下位の T4000 は、メモリが 64 GB、消費電力が 40 から 70 W です。開発用のキットである Jetson AGX Thor Developer Kit は、T5000 を使います。

開発元によれば、T5000 は、前の世代の Jetson AGX Orin と比べて、AI の計算の性能が最大7.5倍、電力あたりの性能が3.5倍です。

Isaac GR00T、Isaac の各ソフトウェア、そしてセンサーのデータを処理する仕組みの Holoscan を、動かす先として位置づけられています。

状態は実用です。開発元と、販売の協力企業を通じて販売されているためです。一次情報は、開発元の Jetson Thor のページです。

まとめ。

NVIDIA は、フィジカルAIの開発を、学習の DGX、シミュレーションとデータ生成の RTX PRO Server、ロボットの上での実行の Jetson Thor、という3つの計算機の役割で説明しています。

モデルでは、自動運転の VLA の Alpamayo を紹介しました。シミュレーションとデータでは、Omniverse と OpenUSD、PhysX、AlpaSim、GR00T-Mimic と GR00T-Dreams、そして Physical AI データセットを紹介しました。ロボットの上では、Isaac ROS と Jetson Thor を紹介しました。

ただし、NVIDIA の技術で閉じているわけではなく、LeRobot の形式や ROS 2 ともつながっています。一方で、GPU の部分の多くは NVIDIA の GPU が前提で、モデルの重みやデータのライセンスは技術ごとに違うので、使う前に確かめてください。
