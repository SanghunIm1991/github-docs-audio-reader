Isaac Lab を使ったフィジカルAIの開発（その1／全6）

これは、Isaac Lab を使って、ロボットの方策を作る開発の話です。

Isaac Lab は、NVIDIA が開発する、ロボットの学習、つまり強化学習や模倣学習のための、GPU で並列に動く枠組みです。原文のファイルは、Isaac Lab で実際に方策を作るエンジニア向けに、ほかのファイルより一歩踏み込んで、環境の設計、学習、実機への展開の要点と、周辺の道具を整理しています。

Isaac Lab の位置づけや、ほかのシミュレータとの違いは、シミュレータのファイルで、NVIDIA の技術全体の中での位置づけは、NVIDIA のファイルで説明しています。原文は、それらを先に読むよう勧めています。

前提と、このファイルの範囲。

前提の知識は、強化学習の基本と、Python と PyTorch を使えることです。強化学習の基本とは、方策、報酬、PPO などのことです。用語は、Isaac Lab の公式の文書の英語の名前、つまりクラス名や設定の名前を、そのまま併記しています。

版の扱いはこうです。確認した時点で、安定の版は 2.3 系で、2.3.2 が最後です。3.0 は先行の版、EA です。原文の説明は、2.3 系の公式の文書を土台にし、3.0 で変わる点はその都度書いています。また、成功率や時間などの数字は、特に断らない限り開発元の文書が示す値で、条件が違えば変わります。

選び方はこうです。開発の流れ、つまり環境を作る、学習させる、評価する、実機に移す、の各段階から、Isaac Lab の公式の文書が案内している道具と手引きを選びました。強化学習のライブラリは、2.3 系の文書の比較の表に載る4つのうち、2つを項目にしました。1つは RSL-RL で、その論文の著者に、Isaac Lab の技術報告の筆頭の著者が含まれます。もう1つは skrl で、同じ表で文書が最も充実している、Comprehensive とされています。

今回は載せていないものもあります。四脚の歩行や手の操作などの、個々の学習の環境の解説。コンテナや Ray などを使った、クラウドやクラスタでの運用。そして、アセットの作り方や ROS とつなぐ仕組みといった、Isaac Sim 側の機能の詳細です。

版の選び方。

原文には、版の表があります。表の列は、版、対応する Isaac Sim、状況、の3つで、3行あります。

1行目は、2.3 系です。リポジトリの main の枝にあたります。対応する Isaac Sim は、4.5、5.0、5.1 です。正式な版で、2026年2月2日の 2.3.2 が、main の枝の最後の版です。開発は 3.0 に移りました。

2行目は、3.0.0-EA です。対応する Isaac Sim は 6.1 です。2026年9月16日に出た先行の版です。開発元は、正式な版、つまり GA を、2026年10月末に出すことを目標にしています。

3行目は、release/3.0.0 の枝と、develop の枝です。対応する Isaac Sim は 6.2 です。3.0 の正式な版に向けた、開発中のものです。

3.0 では、内部の構成が大きく変わります。これは、GitHub のリリースの一覧にある、3.0.0-EA と beta の説明によります。変わる点は3つです。

1つ目は、計算の部分を選べることです。物理の計算、描画、可視化を、それぞれ別に選べます。物理の計算の選択肢は、Isaac Sim の PhysX、Newton、そして Kit を使わない PhysX である OVPhysX です。対応する環境は、環境のコードを書き換えずに切り替えられます。

2つ目は、Isaac Sim なしで動かせることです。Newton の物理と描画を使えば、Isaac Sim、つまり Omniverse Kit を入れずに学習できます。Isaac Sim が要るのは、XR の遠隔操作、ROS とつなぐ仕組み、Isaac Sim の PhysX や RTX の描画を使う場合などに限られます。

3つ目は、互換性のない変更です。2.3 系のコードを移すときは、リリースノートの一覧で確かめるよう、原文は勧めています。主なものは5つです。

1つ目。四元数の並びが、WXYZ から XYZW に変わります。

2つ目。状態を読む属性、つまりドット data ドット何々、という属性が、torch.Tensor ではなく、Warp の配列を包んだ ProxyArray を返すようになります。PyTorch のテンソルとして使うには、ドット torch で取り出します。

3つ目。描画を出さずに動かす指定が、ハイフン2つの headless から、ハイフン2つの viz に変わります。

4つ目。TiledCamera が Camera に統合されます。

5つ目。これまでのスクリプトの isaaclab.sh は非推奨になり、操作は1つのコマンドにまとまります。形は、uv run isaaclab の後にサブコマンドを続けるものです。例えば、学習は、uv run isaaclab train に、使う強化学習のライブラリと課題の名前を指定します。原文の例では、ライブラリに rsl_rl を指定しています。学習させた方策の再生は play、課題の一覧は list_envs というサブコマンドです。使うライブラリや、計算の部分の追加の部品は、uv run の後にハイフン2つの extra で指定します。例えば、skrl を使うなら、uv run ハイフン2つ extra skrl isaaclab、と続けます。これは 3.0 の文書によります。

Newton の扱いも、版で違います。2.3 系の文書では、Newton との連携は試験的な機能とされ、対応する環境は、古典的な課題と平地の歩行に限られていました。3.0 の文書では、物理の計算の部分の1つとして説明されています。ソルバーは、主に確かめられた経路である MuJoCo Warp、略して MJWarp のほか、剛体向けの Kamino、布や柔らかい物体向けの VBD、粒子の材料向けの MPM などを選べます。どの課題がどの計算の部分に対応するかは課題ごとに違うので、各課題のヘルプや環境の一覧で確かめます。
