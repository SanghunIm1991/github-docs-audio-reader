# フェーズ5-1: 車両の疑似プラントを作り、Gazebo で動きを見る（聞くための原稿）

これは、ros2MinimalPhysicalAi という教材の、フェーズ5-1 の手順書の話です。学習計画のフェーズ5 の5-1、元のアイデアのステップ2 にあたります。1次元、つまり前後の動きだけの車両の、疑似プラントを自作します。疑似プラントとは、制御の対象になる車両の動きを、数式で計算するノードのことです。数式の中身、つまり数理モデルを作ることが、この手順書の中心です。計算した速度は、フェーズ5-0 で動かした Gazebo の緑の車両に送って、目で見える形にします。

想定する環境は、WSL2 と Ubuntu 24.04 と ROS2 Jazzy です。前提は3つです。フェーズ3-1 の Publisher と Subscriber、フェーズ3-3 のパラメータの宣言と、変更を検証するコールバック、そしてフェーズ5-0 で、Gazebo のデモを起動できて、learn_py の package.xml に geometry_msgs があることです。フェーズ4 の launch は、この手順書ではまだ使いません。使うのはフェーズ5-3 からです。所要時間の目安は2コマで、言語は Python です。

原文の進め方の囲みです。前半の2節で、車両に働く力と、アクセルとブレーキの遅れを式にし、落ち着く速さと、落ち着くまでの時間の目安を示します。式からの求め方は、フェーズ5 の後の任意の間章、古典制御の間章で扱います。4節で、その式を、ROS2 を使わない Python のクラスとして書き、計算の結果が2節の値と合うことを確かめます。5節でクラスをノードで包み、6節で、ログと Gazebo の画面で動きを見ます。サンプルは学習の手がかりとして最小限に書いたもので、公式のチュートリアルの転載ではありません。

確かめた範囲も書いてあります。コードは手順書を作るときに、ビルドと import まで確かめました。Gazebo を使わない部分、つまり6-1節と6-3節と、gz_display が速度を縮尺して送ることは、使い捨ての環境でノードを起動して確かめました。Gazebo と組み合わせた動きは、画面なしの Gazebo で、オドメトリの速度が縮尺どおりに変わることと、vehicle_plant を止めると車両が止まることまで確かめました。画面の見え方は確かめていないので、出力が違うときは、実機の表示を優先します。

期待する結果の出どころの囲みもあります。4節のモデルだけの計算の結果は、使い捨ての環境で実際に実行した表示で、同じコードなら同じ数値になります。5-3節のビルドの表示は、使い捨ての環境で確かめた表示の形です。ノードを起動した後の表示のうち、Gazebo を使わない部分、つまり6-1節と6-3節の vehicle_plant のログと ros2 param の表示、6-2節の最後の gz_display のログは、使い捨ての環境で実際に実行した表示です。時刻と、ペダルを送った時刻による数値の細部は、実行ごとに違います。6-2節のオドメトリの値は、使い捨ての環境で Gazebo を画面なし、つまり gz sim の -s で起動し、ブリッジを手で起動して確かめた表示です。6-2節の画面の様子は、筆者が想定したものです。

この原稿では、数式は記号の意味を添えて言葉で読み、サンプルコードは書き写さずに、ブロックの役割と要の行を言葉で説明します。

## 0. 学習目標と完了の条件

学習目標は4つです。

1つ目。車両に働く力、つまり駆動力、制動力、転がり抵抗、速度に比例する抵抗と、アクセルとブレーキの遅れ、つまり一次遅れを式で書き、それぞれのパラメータ、特に時定数の意味を説明できる。

2つ目。微分方程式を、オイラー法で1ステップずつ計算するコードを書き、計算の刻み幅を時定数より十分短くする理由を説明できる。

3つ目。数理モデルを ROS2 に依存しないクラスに分け、ノードで包む理由を説明できる。

4つ目。車両のパラメータ、特に時定数を実行中に変え、動きの変わり方を、ログと Gazebo で確かめられる。

完了の条件です。ペダル0.5 を踏み続けると、速度が毎秒約9.1メートル、つまり2-3節の値へ近づくことをログで確かめ、Gazebo の緑の車両が同じように加速して、一定の速さに落ち着く様子を見ます。そして、tau_accel を大きくすると、加速の立ち上がりが遅くなる理由を、2-2節の式で説明できることです。

## 2. 数理モデル

### 2-1. 車両に働く力

車両は前後にだけ動くものとし、前向きの速さを v、単位は毎秒メートルとします。車両に働く力は4つで、表は4列、4行です。列は、力、記号、向き、大きさです。

1行目は駆動力、つまりアクセルの力で、記号は F の d です。向きは前向きで、大きさは、アクセルの踏み込みに応じて、2-2節の遅れで変わります。

2行目は制動力、つまりブレーキの力で、記号は F の b です。向きは後ろ向きで、大きさは、ブレーキの踏み込みに応じて、2-2節の遅れで変わります。

3行目は転がり抵抗で、記号は F の r、その大きさは、ミュー かける m かける g です。向きは後ろ向きで、大きさは一定です。タイヤが変形しながら転がることによる抵抗で、ミューは転がり抵抗の係数、m は質量、g は重力加速度です。

4行目は、速度に比例する抵抗で、記号は c かける v です。向きは後ろ向きで、大きさは速さに比例します。空気抵抗などをまとめて、線形にしたもので、c は係数です。

ニュートンの運動方程式、つまり、質量かける加速度は力の合計に等しい、という式から、速度の変わり方は次の式で決まります。m かける、v の時間による微分、イコール、F の d、マイナス F の b、マイナス ミュー m g、マイナス c v。言いかえると、質量かける速度の変化の速さが、駆動力から、制動力と転がり抵抗と速度に比例する抵抗を引いたものに等しい、という式です。

ただし、この車両は後ろへは進まないものとします。ブレーキと転がり抵抗は、本来、動きを止める向きにしか働かないので、止まった車両を後ろへ押すことはありません。この式のままだと、止まった後も後ろ向きの力で v が負になってしまうので、計算では、v が0 を下回ったら0 にそろえます。4節の、velocity と0.0 の大きい方を取る、max の行がそれです。

### 2-2. アクセルとブレーキの遅れ、一次遅れ

ペダルを踏んでも、力はすぐには出ません。エンジンやモーターが回転を上げるまで、ブレーキの油圧が高まるまでには、少し時間がかかります。この遅れを、一次遅れの式で表します。

式は2つあります。1つ目は、タウ の a かける、F の d の時間による微分、イコール、u の a かける F の d の max、マイナス F の d。2つ目は、ブレーキについて同じ形で、タウ の b かける、F の b の時間による微分、イコール、u の b かける F の b の max、マイナス F の b です。

記号の意味は4つにまとめられます。

1つ目。u の a と u の b は、アクセルとブレーキの踏み込みで、0 から1 の値です。ペダルの指令は、マイナス1 から1 の1つの数 u で受け取り、正ならアクセル、つまり u の a を u に、負ならブレーキ、つまり u の b をマイナス u にします。

2つ目。F の d の max と F の b の max は、踏み切ったときの力です。右辺の、u の a かける F の d の max が、出したい力で、今の力 F の d との差に比例する速さで近づいていきます。

3つ目。タウ の a と タウ の b が時定数で、単位は秒です。ペダルを急に踏むと、力は、時定数の時間で目標の約63パーセント、3倍の時間で約95パーセントに達します。時定数が大きいほど、ゆっくり立ち上がります。

4つ目。止まった状態、つまり F の d が0 から、アクセル u の a を踏み続けると、駆動力は、u の a かける F の d の max かける、1 マイナス、e の マイナス t 割る タウ の a 乗、と増えていきます。e は約2.718 で、自然対数の底です。t が タウ の a のときは、1 マイナス e の マイナス1 乗で約0.63、t が タウ の a の3倍のときは、1 マイナス e の マイナス3 乗で約0.95 になります。これが、さきほどの63パーセントと95パーセントの出どころです。この式が一次遅れの式の解になる理由は、古典制御の間章の2-1節で扱います。

アクセルとブレーキに別々の時定数を持たせているのが、このモデルの特徴です。既定値は、アクセルが0.5秒、ブレーキが0.2秒です。加速させるときと減速させるときで効き方が違う車両を、フェーズ5-2 の PI 制御でどう扱うかが、後の題材になります。

### 2-3. 定常速度と時定数

ペダルを u のまま踏み続けると、力が目標に達し、つまり F の d が u かける F の d の max になり、F の b が0 になって、やがて速度も変わらなくなります。このときの速度を、定常速度、v の ss と呼びます。2-1節の式の左辺を0、つまり速度が変わらないとして、v について解くと求まります。速度がそこへ近づく速さの目安は、速度の時定数、大文字の T で表せます。力の時定数と同じく、T 秒で約63パーセント、3T 秒で約95パーセントに達します。T の求め方は、古典制御の間章の2-2節で扱います。

式は2つです。定常速度 v の ss は、u かける F の d の max から、ミュー m g を引いて、c で割ったものです。速度の時定数 T は、m 割る c です。

既定値、つまり2-5節の表の、ミューが0.015、m が1500キログラム、F の d の max が3000ニュートン、c が毎秒メートルあたり140ニュートンと、重力加速度 g の9.81 を入れると、次のようになります。

ペダル0.5 では、定常速度は毎秒約9.14メートル、時速でおよそ33キロメートルです。

ペダル1.0、つまり全開では、毎秒約19.85メートル、時速でおよそ71キロメートルです。

ペダルが約0.074 より小さいと、駆動力が転がり抵抗、約220.7ニュートンに負けて、車両は動き出しません。

速度の時定数は、1500 割る140 で、約10.7秒です。これはペダルの踏み込みによりません。ペダル0.5 なら、約11秒で定常速度の約63パーセント、つまり毎秒約5.8メートル、約32秒で約95パーセント、つまり毎秒約8.7メートルに達します。

4節で、モデルの計算の結果を、この値と見比べます。

### 2-4. オイラー法で計算する

2-1節と2-2節の式は、今の状態から、変化率、つまり1秒あたりの変化が決まる、という形をしています。状態は、v、F の d、F の b の3つです。コンピュータでは、短い時間、デルタ t ごとに、次の式で状態を少しずつ進めます。これをオイラー法と呼びます。

式は、x の k プラス1、イコール、x の k、プラス、デルタ t かける、k 回目の変化率、です。x の k は k 回目の状態で、変化率はそのときの x の時間による微分です。3つの状態それぞれについて、今の状態から変化率を全部求めてから、まとめてデルタ t だけ進めます。この手順書では、デルタ t を0.01秒、つまり1秒に100回とします。

オイラー法は簡単ですが、デルタ t が時定数に比べて長すぎると、計算が振動したり、発散したりします。一次遅れの式では、デルタ t が時定数 タウ より長いと、目標をまたいで、振動しながら近づきます。これは実物には無い振動です。2 タウ より長いと、振れ幅が大きくなって発散し、値が際限なく大きくなります。理由は、古典制御の間章の2-3節で扱います。

デルタ t が0.01秒なら、時定数が0.01秒より長い限り、なめらかに計算できます。既定値の0.2秒と0.5秒には、十分な余裕があります。6-3節で時定数を実行中に変えられるようにするので、とても小さな値を入れると、この問題が起きることは覚えておきます。6-3節の最後の課題3で確かめます。

先に力を更新し、その力で速度を進めるほうが自然ではないか、という疑問と、更新の順番による違いの大きさは、Tips集の9節で扱います。

### 2-5. パラメータと既定値

5列の表で、8行あります。列は、パラメータ名、記号、既定値、単位、既定値の考え方です。

mass は m で、1500.0キログラムです。乗用車の大まかな質量です。

drive_force_max は F の d の max で、3000.0ニュートンです。質量1500キログラムで、止まった状態から、毎秒毎秒約2メートルで加速できる力です。

brake_force_max は F の b の max で、9000.0ニュートンです。毎秒毎秒約6メートルで減速できる力で、アクセルより強くしてあります。

tau_accel は タウ の a で、0.5秒です。駆動力の立ち上がりの遅れで、筆者が目安として選んだ値です。

tau_brake は タウ の b で、0.2秒です。制動力の立ち上がりの遅れで、アクセルより速く効く想定で、筆者が目安として選んだ値です。

rolling_coeff は ミュー で、0.015 で、単位はありません。舗装路の乗用車のタイヤで一般的に言われる範囲、0.01 から0.015 程度から選んでいます。

drag_coeff は c で、毎秒メートルあたり140.0ニュートンです。アクセル全開の定常速度が毎秒約20メートルになるように選んだ値です。

period は デルタ t で、0.01秒です。計算の周期、つまりオイラー法の刻み幅です。

時定数などの値は、実在の特定の車両から測ったものではなく、動きが分かりやすく、現実から大きく外れない範囲で選んだものです。6節で、実行中に変えて違いを見ます。

抵抗を線形にした理由の補足があります。一般的なモデルでは、空気抵抗は速さの2乗に比例します。このサンプルでは、2-3節の定常速度と時定数を式で求められるように、速さに比例する形、つまり線形にしました。係数 c は、アクセル全開の最高速度を毎秒約20メートルに収める役も担うので、本物の空気抵抗を線形にした値より、かなり大きくなっています。実務で実物に近づけたいときは、空気抵抗を2乗の式にし、駆動力に出力の上限、つまり速くなるほど出せる力が減る、という性質を入れます。制御器を設計するときには、逆に、ある速度の付近で線形に近似したモデルを使うことが多い、とあります。一般的なモデルとの違いの詳しい説明は、古典制御の間章の2-4節で扱います。

## 3. 仕様

パッケージは、フェーズ3-1 から使っている learn_py に、ファイルを3つ足します。表は2列で、3行あります。

vehicle_model.py は、2節の式を計算するクラス VehicleModel と、パラメータをまとめる VehicleParams です。ROS2 を使いません。つまり import rclpy をしません。

plant_node.py は、VehicleModel を包むノード vehicle_plant で、実行ファイル名も vehicle_plant です。

gz_display.py は、表示用のノード gz_display で、実行ファイル名も gz_display です。

vehicle_plant の仕様は4つです。

受けるのは /plant/pedal で、型は std_msgs の msg の Float64 です。マイナス1 から1 の範囲の外の値は、範囲の端にそろえます。次の指令が来るまで、同じ値を踏み続けます。

送るのは /plant/velocity で、型は同じく Float64、単位は毎秒メートルで、period 秒ごとに送ります。

パラメータは、2-5節の表の8つです。実行中に ros2 param set で変えられます。rolling_coeff と drag_coeff は0 以上、それ以外は正の値だけを受け付けます。

ログは、1秒に1回、ペダル、速度、駆動力、制動力を出します。

gz_display の仕様は4つです。

受けるのは /plant/velocity です。

送るのは /model/vehicle_green/cmd_vel で、型は geometry_msgs の msg の Twist です。その linear の x に、速度かける scale を入れて送ります。

パラメータは scale で、既定は0.025、つまり40分の1です。

/plant/velocity が0.5秒以上届かなければ、停止の指令を1回送ります。

トピックの型は、速度もペダルも1つの数なので、いちばん単純な Float64 にしました。位置や向きまで含む、フェーズ5-0 で見た nav_msgs の Odometry は、前後の速さだけを扱うこの車両には大きすぎます。フェーズ5-2 の PI 制御のノードも、この2つのトピックをそのまま使います。フェーズ5-4 でプラントを Gazebo の物理に差し替えるときも、この2つのトピックの名前、型、単位、つまりペダルはマイナス1 から1、速度は実車の毎秒メートル、を保つので、PI 制御のノードを変えずに、つなぎ替えられます。

縮尺を40分の1にしたのは、フェーズ5-0 の2節の表のとおり、Gazebo の車両の最高の速度が、毎秒0.5メートルだからです。アクセル全開の毎秒約20メートルが、40分の1で、毎秒約0.5メートルに収まります。縮尺は、gz_display が送る直前にかけるだけなので、vehicle_plant の計算には影響しません。

主な API、つまりこれまでの手順書で使ったもの以外の表は、2列で、4行あります。

Python 標準の dataclasses の、アットマーク dataclass は、値をまとめて持つだけのクラスを、フィールドと既定値を並べるだけで作ります。

dataclasses の fields にクラスを渡すと、データクラスのフィールドの一覧が得られます。パラメータを、名前の一覧から一括で宣言するのに使います。

dataclasses の replace に、インスタンスと、名前と値の組を渡すと、一部のフィールドだけを変えた、新しいインスタンスを作ります。

std_msgs の msg の Float64 は、実数1つの型で、値は msg の data です。

## 4. 数理モデルを ROS2 なしで確かめる

まず、2節の式だけを書いたファイルを作り、ROS2 を使わずに、計算の結果を確かめます。

サンプルは、learn_py の learn_py フォルダの vehicle_model.py です。

vehicle_model.py は、65行ほどのコードで、ブロックは4つです。1つ目は、dataclass の import と、重力加速度の GRAVITY を9.81 とする定数です。2つ目は、アットマーク dataclass を付けた VehicleParams のクラスで、2-5節の表のうち period を除いた7つのフィールドを、既定値と単位のコメント付きで並べます。3つ目は VehicleModel のクラスで、__init__ はパラメータを受け取り、速度、駆動力、制動力の3つの状態を0 で始めます。要の行は step のメソッドにあります。ペダルをマイナス1 から1 にそろえ、アクセルの踏み込み accel_cmd とブレーキの踏み込み brake_cmd に分けたあと、今の状態から、3つの変化率、d_drive、d_brake、d_velocity を求めます。d_drive は、accel_cmd かける drive_force_max から、今の駆動力を引いて、tau_accel で割ったものです。d_velocity は、駆動力から、制動力と、転がり抵抗と、drag_coeff かける速度を引いて、質量で割ったものです。そのあと、3つの状態に、変化率かける dt をまとめて足し、最後に、速度と0.0 の大きい方を取ってから、速度を返します。4つ目は main で、ROS2 を使わずに、刻み幅0.01秒で40秒分を計算し、最初の30秒はペダル0.5、その後はマイナス0.3 にして、決めた時刻の行だけを、時刻、ペダル、速度、駆動力、制動力の表にして表示します。ファイルの最後は、直接実行したときだけ main を呼ぶ、if __name__ の2行です。

原文の解説の要点です。

VehicleParams は、2-5節の表の7つの値を、既定値付きで並べたデータクラスです。アットマーク dataclass を付けると、VehicleParams を引数なしで呼べば既定値のまま、tau_accel だけを3.0 にして呼べば一部だけ変えて作れます。__init__ を自分で書かなくてかまいません。単位は、すべて SI、つまりキログラム、ニュートン、秒、毎秒メートルです。period、つまり計算の周期は、ここに含めず、step の引数の dt として渡します。周期は、モデルの性質ではなく、どれだけ細かく計算するか、の設定だからです。

VehicleModel の __init__ では、状態は、速度、駆動力、制動力の3つで、2-4節の v、F の d、F の b にあたります。止まった状態、つまりすべて0 から始めます。

main は、ROS2 を使わずに、モデルだけを40秒分計算します。4000ステップのうち、表示する時刻の一覧に挙げた行だけを表示します。

if __name__ の行は、このファイルを python3 で直接実行したときだけ main を呼ぶためのものです。5節のノードから import したときは呼ばれません。

ファイルを保存したら、ビルドせずにそのまま実行できます。ROS2 を使わないので、source も要りません。コマンドは、python3 に、ros2_ws の src の learn_py の learn_py の vehicle_model.py を渡すものです。

## 5. ノードで包む

### 5-1. 疑似プラントのノード、plant_node.py

サンプルは、learn_py の learn_py フォルダの plant_node.py です。

plant_node.py は、80行ほどのコードで、ブロックは6つです。1つ目は import で、dataclasses、rclpy、SetParametersResult、ExternalShutdownException、Node、Float64 と、同じパッケージの vehicle_model から、VehicleModel と VehicleParams を読み込みます。

2つ目は、Node を継承した VehiclePlant のクラスの __init__ です。ノード名は vehicle_plant です。要の行は、dataclasses の fields で VehicleParams のフィールド名の一覧を作り、その名前ごとに、VehicleParams の既定値で declare_parameter をするループと、period を0.01 で宣言する行です。続いて、宣言したパラメータの値を辞書に読み、それを展開して VehicleParams を作り、VehicleModel に渡します。周期を読み、ペダルを0.0 にしておき、plant/pedal の購読、plant/velocity の Publisher、周期のタイマーを作り、パラメータの変更のコールバック on_params を登録します。

3つ目は on_pedal で、届いた値を self.pedal に覚えるだけです。

4つ目は on_timer で、要の行は、モデルの step に、覚えておいたペダルと周期を渡して速度を得る行です。その速度を Float64 に入れて publish し、ペダル、速度、駆動力、制動力を、throttle_duration_sec の1.0 を付けて、1秒に1回ログに出します。

5つ目は on_params で、1回目のループで検証し、rolling_coeff と drag_coeff は0 より小さいと、それ以外のモデルのパラメータと period は0 以下だと、理由付きで失敗を返します。検証に通ったら、モデルのパラメータの変更分を集め、要の行の、dataclasses の replace で、モデルの params を差し替えます。period が変わったときは、タイマーを止めて作り直します。最後に成功を返します。

6つ目は main で、フェーズ3-1 の talker と同じです。

原文の解説の要点です。役割は、4節の VehicleModel を、トピックとパラメータで ROS2 につなぐことです。式は、このファイルに1行もありません。計算はすべてモデルの step に任せ、ノードは、指令を受け取る、周期的に計算を進める、結果を送る、パラメータを受け付ける、だけを受け持ちます。

import では、learn_py の vehicle_model から読み込むことで、同じパッケージの4節のファイルを使います。ビルドすると、learn_py パッケージの中のモジュールとして import できるようになります。

__init__ のパラメータの宣言について、3つの点があります。1つ目。dataclasses の fields で、VehicleParams のフィールド名、つまり mass、drive_force_max などの一覧を得て、同じ名前のパラメータを、VehicleParams の既定値で宣言します。フィールドを7つ並べて declare_parameter を7行書く代わりに、ループで書いています。こうしておくと、VehicleParams にフィールドを足すだけで、パラメータも自動で増えます。2つ目。既定値は1500.0 のように小数点付きなので、パラメータの型は実数、double になります。フェーズ3-3 の5-3節のとおり、ros2 param set で整数を渡すと、型の不一致で拒否されます。3つ目。宣言の後、get_parameter で値を読み、つまり起動のときに -p などで指定されていればその値を読み、アスタリスク2つの values で VehicleParams を作って、モデルに渡します。アスタリスク2つの values は、mass が1500.0、のような辞書を、mass イコール1500.0、の形の引数に展開する、Python の書き方です。

on_pedal は、届いた値を覚えるだけで、計算はここでは行いません。ペダルの指令が、いつ、どのくらいの頻度で届いても、計算の周期は一定に保ちたいからです。

on_timer は、period 秒ごとに、モデルを period 秒分だけ進めて、速度を送ります。計算の刻み幅として、タイマーの周期の値をそのまま使っています。実際の呼び出しの間隔は少し揺れますが、計算の上では、ちょうど period 秒進んだとみなします。この揺れの影響は小さい、とあります。ログは、フェーズ5-0 の5-1節と同じく、1秒に1回に間引きます。

on_params は、フェーズ3-3 の param_talker と同じく、1回目のループで検証し、残りで反映します。車両のパラメータは、dataclasses の replace で、変更分だけを入れ替えた新しい VehicleParams を作り、モデルの params を差し替えます。モデルの状態、つまり速度、駆動力、制動力はそのままなので、走っている途中で時定数を変えても、その瞬間から新しい時定数で計算が続きます。period を変えたときは、フェーズ3-3 と同じく、タイマーを作り直します。use_sim_time など、ノードが自動で持つパラメータの変更は、どちらの if にも当たらないので、検証も反映もせずに受け入れます。

main は、フェーズ3-1 の talker と同じです。

起動のときの値を検証していない理由、の補足があります。3つの点に分かれています。

一般的な書き方です。外から受け取る値は、実行中の変更だけでなく、起動のときに -p や YAML で渡された値も検証します。やり方は、__init__ で値を読んだ直後に、on_params と同じ検証をかけることです。rclpy は、パラメータを宣言した時点で、登録済みの検証のコールバックを呼ぶので、コールバックを宣言より前に登録する方法もあります。ただし、このサンプルの on_params は、検証だけでなく反映、つまりモデルの書き換えやタイマーの作り直しもしているので、そのまま前へ移すと、宣言の時点ではまだモデルやタイマーが無く、失敗します。前へ移すなら、検証だけの関数に分けます。

このサンプルで検証していない理由です。このノードは、宣言と値の読み込みを済ませてから、最後に on_params を登録しています。そのため、on_params が確かめるのは、実行中の変更、つまり ros2 param set だけで、起動のときに、-p で tau_accel を0.0 にするように0 を渡すと、そのままモデルに入り、最初の計算で0 で割って、ZeroDivisionError でノードが止まります。止まるのはシミュレーションだけで、起動し直せば元に戻ります。起動のときの検証まで書くとコードが膨らみ、パラメータの受け取り方という学習の要点が見えにくくなるので、あえて省いている、とあります。

実務の目安です。実物の機器につながるノードでは、不正な値で止まると、機器が動きの途中で放っておかれかねないので、起動のときの値も必ず検証し、不正なら分かりやすいメッセージで起動を止めます。

### 5-2. 表示用のノード、gz_display.py

サンプルは、learn_py の learn_py フォルダの gz_display.py です。

gz_display.py は、65行ほどのコードで、ブロックは5つです。1つ目は import で、rclpy、Twist、SetParametersResult、rclpy の clock の Clock と ClockType、ExternalShutdownException、Node、Float64 を読み込みます。

2つ目は、Node を継承した GzDisplay のクラスの __init__ です。ノード名は gz_display で、scale を0.025 で宣言して読みます。要の行の1つは、ClockType の STEADY_TIME、つまり単調に増える時計で Clock を作り、steady_clock に入れる行です。最後に速度を受け取った時刻の last_received は、None で始めます。続いて、/model/vehicle_green/cmd_vel への Twist の Publisher、plant/velocity の購読、0.1秒ごとに on_watchdog を呼ぶタイマーを作り、on_params を登録します。

3つ目は on_velocity で、受け取った時刻を steady_clock で記録し、Twist の linear の x に、届いた速度かける scale を入れて publish します。

4つ目は on_watchdog で、要の行は、last_received が None でなければ、steady_clock の今の時刻との差を秒に直し、0.5 を超えていたら、空の Twist、つまり停止の指令を publish して、last_received を None に戻し、plant/velocity がタイムアウトしたので停止の指令を送った、というログを出す部分です。

5つ目は on_params で、scale が0 以下なら失敗を返し、そうでなければ scale を反映します。ファイルの最後の main は、これまでと同じです。

原文の解説の要点です。

on_velocity は、速度が届くたびに、縮尺をかけて Twist の linear の x に入れて送ります。フェーズ5-0 の gz_drive の on_timer と同じ形で、送る値が一定の0.3 ではなく、プラントの速度かける縮尺になっただけです。vehicle_plant が100ヘルツで送るので、Gazebo への指令も100ヘルツになります。

on_watchdog は、途絶えの見張りです。Gazebo の車両、つまり DiffDrive は、フェーズ5-0 の4-3節のとおり、最後に受け取った指令を持ち続けます。そのため、vehicle_plant を止めると、Gazebo の車両は、最後の速度のまま走り続けてしまいます。0.1秒ごとに、最後に速度が届いてから何秒たったかを調べ、0.5秒を超えたら、停止の指令、つまり全部のフィールドが0 の Twist を1回送ります。一定の時間、指令が途絶えたら止める仕組みは、実物のロボットでもよく使われ、ウォッチドッグと呼ばれます。

経過した時間は、__init__ で作った steady_clock、つまり ClockType の STEADY_TIME の、単調に増える時計で測ります。2つの時刻の差は Duration になり、その nanoseconds でナノ秒の整数を取り出して、秒に直しています。

ノードの時計、つまり get_clock を使わないのは、ノードの時計がふつうは PC の現在の時刻で、NTP などの時刻合わせで数秒飛ぶことがあるからです。現在の時刻が前へ飛ぶと、速度が届いているのに、0.5秒以上届いていない、と誤って判定し、停止の指令を送ってしまいます。手順書を作るときに、使い捨ての環境で実際に起きた、とあります。単調に増える時計は、時刻合わせの影響を受けず、戻ったり飛んだりしません。一般に、タイムアウトや処理の時間など、経過した時間を測るときは単調に増える時計、ログの記録など、いつ起きたかを残すときは現在の時刻を使います。

停止の指令を送った後は、last_received を None に戻し、何度も送らないようにしています。

on_params は、scale を正の値に限って受け付けます。実行中に縮尺を変えると、その後に届いた速度から、新しい縮尺で送られます。

gz_display 自身を先に Ctrl+C で止めた場合は、停止の指令を送る前に終わるので、Gazebo の車両は走り続けます。止める順は、vehicle_plant が先、gz_display が後にします。

### 5-3. 実行ファイルとして登録し、ビルドする

## 7. 時定数をパラメータにした理由、フィジカル AI へのつながり

このプラントでは、アクセルとブレーキの時定数を、起動のときにも実行中にも変えられるようにしました。これは、この教材の先の課題のための準備です。

実物の車両やロボットでは、アクチュエータ、つまりモーターやブレーキの遅れ方は一定ではありません。部品のすり減り、温度、積んだ荷物の重さ、車両ごとの個体差で変わります。ある時定数に合わせて調整した制御、つまりフェーズ5-2 の PI のゲインは、時定数が変わると、追いつくのが遅れたり、行き過ぎたりするようになります。PI のゲインとは、目標の速度との差からペダルの踏み込みを決めるときの、効き方の強さを表す係数です。

フェーズ6 の後の、最終のゴールに向かうフェーズ7、つまり元のアイデアのステップ6 では、PI のゲインの調整を、強化学習のエージェントに任せます。このプラントのように、時定数をパラメータとして外から変えられれば、次の3つを試せます。

1つ目。時定数を変えたプラントで、同じゲインの制御が、どれだけ悪くなるかを測る。フェーズ7 では、ブレーキの時定数を1.0秒にした、ブレーキの遅いプラントを題材にします。任意のフェーズ7-2 では、手で決めたゲインが合わなくなることを確かめ、強化学習でゲインを調整し直します。

2つ目。時定数をばらつかせて、どの時定数でもそこそこ動くゲインを探す。シミュレーションで条件をばらつかせて学習させる方法は、ドメインランダマイゼーションと呼ばれ、シミュレーションで学習した AI を実物に移すときによく使われます。任意のフェーズ7-2 の2-7節では、ブレーキの時定数を0.2秒から1.0秒で変えると、1組の固定のゲインで、改善の大部分が得られることを紹介します。

3つ目。実行中に時定数が変わったことを、プラントの応答から推定して、ゲインを切り替える。上の結果、つまり固定の1組で大部分が得られることから、この教材では扱いません。

6-3節で、実行中に時定数を変えても計算が続くことと、変えすぎると数値の計算が壊れること、つまり6-3節の最後の課題3の、時定数を刻み幅の半分より小さくすると発散すること、を確かめました。時定数をばらつかせる範囲を決めるときは、2-4節の条件、つまり刻み幅より十分長いこと、を守る必要があります。

変わるのは、時定数だけではありません。フェーズ5-4 では、車体の部分、つまり質量と抵抗を、自作の式から Gazebo の物理に差し替え、式と物理の違いで、同じゲインの制御の効き方が変わることを確かめます。

## 8. このフェーズのまとめ

まとめは5つです。

1つ目。車両の速度は、駆動力、制動力、転がり抵抗、速度に比例する抵抗のつり合いで決まります。抵抗を線形にしたので、定常速度、つまり、u かける F の d の max から ミュー m g を引いて c で割ったものと、速度の時定数、つまり m 割る c を、式で求められます。求め方は、古典制御の間章の2-2節にあります。

2つ目。アクセルとブレーキの遅れは一次遅れで表し、時定数の時間で、目標の約63パーセントに達します。アクセルとブレーキで時定数を分けると、加速と減速で効き方の違う車両になります。

3つ目。微分方程式は、オイラー法で1ステップずつ計算します。刻み幅は、時定数より十分短くします。長すぎると、実物には無い振動や発散が起きます。

4つ目。数理モデルは ROS2 に依存しないクラスに分け、ノードは通信とパラメータだけを受け持ちます。モデルは ROS2 なしで確かめられ、ノードは中身を知らなくても組み立てられます。

5つ目。Gazebo は、縮尺をかけた速度を送る表示器として使いました。DiffDrive は最後の指令を持ち続けるので、指令が途絶えたら止める仕組みを、表示用のノードに入れました。

## 9. つまずきやすい点

2列の表で、10行あります。列は、症状と、確かめることです。

1行目。python3 で vehicle_model.py を実行して、モジュールが見つからない、という ModuleNotFoundError が出る場合。vehicle_model.py の中で、rclpy などを import していないかを確かめます。このファイルは、Python の標準の機能だけで書きます。

2行目。ros2 run learn_py vehicle_plant で、実行ファイルが見つからない、と出る場合。setup.py の entry_points に足したか、足した後に colcon build と source install/setup.bash をしたかを確かめます。5-3節のとおりです。

3行目。vehicle_plant を起動したときに、learn_py の vehicle_model というモジュールが無い、という ModuleNotFoundError が出る場合。vehicle_model.py を、ros2_ws の src の learn_py の、さらに下の learn_py フォルダに置いたかを確かめます。setup.py と同じ階層ではなく、その下の learn_py フォルダの中です。

4行目。ペダルを送っても速度が変わらない場合。トピック名の /plant/pedal と、型の std_msgs の msg の Float64 のつづりを確かめます。ペダルが0.074 より小さいと、転がり抵抗に負けて動きません。2-3節のとおりです。

5行目。ros2 param set で tau_accel を1 にすると失敗する場合。整数を渡しています。1.0 と書きます。フェーズ3-3 の5-3節のとおりです。

6行目。vehicle_plant が、起動した直後に、ZeroDivisionError、つまり0 で割った、で止まる場合。起動のときに、-p や YAML で、時定数の tau_accel や tau_brake、または質量に0.0 を渡しています。整数の0 と書いた場合は、型が合わず、宣言の時点で、InvalidParameterTypeException という別のエラーになります。起動のときの値は検証していません。5-1節の補足のとおりです。0 より大きい値にして、起動し直します。

7行目。Gazebo の車両が動かない場合。ターミナル3 のデモと、ターミナル4 の gz_display が動いているか、ros2 topic list に /model/vehicle_green/cmd_vel があるかを確かめます。

8行目。Gazebo の車両が止まらない場合。gz_display を vehicle_plant より先に止めています。ターミナル2 で、ros2 topic pub に --once を付けて、/model/vehicle_green/cmd_vel に、空の Twist を送ります。フェーズ5-0 の3-3節のとおりです。

9行目。ログの時刻が、途中で数秒飛ぶ場合。PC の時計が、NTP などの時刻合わせで進められたときに起きます。WSL2 で起きることがあります。ログの時刻は現在の時刻なので飛びますが、vehicle_plant の計算は周期の回数で進むので、影響しません。gz_display の途絶えの見張りも、単調に増える時計で測っているので、影響しません。5-2節のとおりです。

10行目。ログの brake が、正と負に大きく振れる場合。時定数を、刻み幅、つまり period に比べて、小さくしすぎています。2-4節と、6-3節の最後の課題3のとおりです。既定値に戻すか、起動し直します。

## 10. 次へ

フェーズ5-2 で、目標の速度に合わせてペダルを自動で踏む PI 制御のノードを作り、このプラントとつないで、ループを閉じます。フェーズ5-3 では、すべてのノードと Gazebo のデモを launch でまとめて起動するので、それまでにフェーズ4 の launch を終えておきます。フェーズ5-4 では、このプラントの車体の部分を、Gazebo の物理に差し替えて比べます。
