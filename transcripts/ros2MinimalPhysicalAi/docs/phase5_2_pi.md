# フェーズ5-2: PI 制御で、目標の速度に追いつかせる（聞くための原稿）

これは、ros2MinimalPhysicalAi という教材の、フェーズ5-2 の手順書の話です。学習計画のフェーズ5 の5-2、元のアイデアのステップ3 にあたります。目標の速度と現在の速度の差から、ペダルをどれだけ踏むかを自動で決める PI 制御のノードを自作し、フェーズ5-1 の疑似プラントとつないで、ループを閉じます。制御の式、つまり数理モデルと、ゲインの決め方が、この手順書の中心です。

想定する環境は、WSL2 と Ubuntu 24.04 と ROS2 Jazzy です。前提は、フェーズ5-1 を終えて、vehicle_plant と gz_display が動くことです。フェーズ4 の launch は、この手順書ではまだ使いません。使うのはフェーズ5-3 からです。所要時間の目安は2コマで、言語は Python です。

## 0. 学習目標と完了の条件

学習目標は4つです。

1つ目。PI 制御の式と、比例、つまり P の項と、積分、つまり I の項の役割を説明し、P 制御だけでは偏差、つまり目標との差が残ることを、シミュレーションで確かめられる。

2つ目。ゲインや条件を変えたときの追いつき方の違いを、シミュレーションで比べて、ゲインを調整できる。

3つ目。ペダルが上限に張り付いたときに起きる積分の飽和、つまりワインドアップと、その対策を説明できる。

4つ目。PI 制御のノードで、フェーズ5-1 のプラントとのループを閉じ、起動のときや実行中にゲインを変えて、追いつき方の違いを、ログと Gazebo で確かめられる。

完了の条件です。目標の速度を、毎秒10メートルから5メートルに変えたとき、行き過ぎなく追いつくことをログで確かめます。そして、P 制御だけにすると毎秒約9.0メートルで止まる理由と、アクセルやブレーキの時定数を変えると、同じゲインでも追いつき方が悪くなる理由を、2-2節と2-4節をもとに説明できることです。

## 2. PI 制御の数理

### 2-1. PI 制御の式

目標の速度を r、現在の速度を v とし、その差を偏差、e とします。e は、r マイナス v です。PI 制御は、ペダルの指令 u を、次の式で決めます。u イコール、K の p かける e、プラス、K の i かける、e を0 から t まで時間で積分したもの。

式の2つの項と、出力の扱いを説明します。

比例、P の項は、K の p かける e です。今の偏差に比例して踏みます。目標より遅いほど強くアクセルを、速すぎるほど強くブレーキを踏みます。K の p を、比例ゲインと呼びます。

積分、I の項は、K の i かける、e の時間による積分です。偏差を、時間で積み上げたものです。偏差が小さくても、残り続ける限り少しずつ大きくなり、踏み込みを足していきます。K の i を、積分ゲインと呼びます。

ペダルの指令はマイナス1 から1 の範囲なので、計算した u が範囲を超えたら、端の値にそろえます。これを飽和と呼びます。

プログラムでは、積分を、フェーズ5-1 の2-4節のオイラー法と同じ考え方で、制御の周期、デルタ t ごとに足し込みます。式は2つです。k プラス1 回目の積分の項は、k 回目の積分の項に、K の i と、k 回目の偏差と、デルタ t を掛けたものを足したもの。そして、k 回目のペダルの指令は、K の p と k 回目の偏差を掛けたものに、k プラス1 回目の積分の項を足したもの、です。原文では、積分の項を大文字の I で書いています。

### 2-2. P 制御だけでは偏差が残る

K の i を0、つまり P 制御だけにすると、目標に届かない偏差が残ります。速度を一定に保つには、抵抗とつり合うだけのペダルが要ります。速度 v を保つのに要るペダルを、u スターと書くと、フェーズ5-1 の2-3節の定常速度の式をペダルについて解いて、u スターは、ミュー m g に c v を足して、F の d の max で割ったもの、になります。ミューは転がり抵抗の係数、m は質量、g は重力加速度、c は速度に比例する抵抗の係数、F の d の max はアクセルを踏み切ったときの力です。毎秒10メートルなら、220.7 に140 かける10 を足して、3000 で割り、約0.54 です。

ところが、P 制御のペダルは、K の p かける e なので、ペダルを0.54 踏み続けるには、偏差が残っていなければなりません。既定の K の p、0.5 で落ち着く速度を式で求めると、目標の毎秒10メートルに対して約9.01メートル、つまり偏差は約1メートル、目標の5メートルに対して約4.44メートルになります。求め方は、古典制御の間章の3-1節で扱います。K の p を大きくすれば偏差は小さくなりますが、0 にはなりません。

積分の項があると、偏差が残る限り、積分の項が増え続けるので、積分の項が必要な踏み込み、つまり0.54 に達して、偏差が0 になったところで、ようやく変化が止まります。積分の項は、速度を保つのに必要な踏み込みを、自分で探し当てる役を担います。転がり抵抗や、速度に比例する抵抗の大きさを知らなくても、偏差を0 にできるのは、このためです。

### 2-3. ゲインの目安を式で求める

ゲインは、当てずっぽうで探す前に、式で目安を立てるのがふつうです。プラントを一次遅れに近づけて考えると、積分ゲインの K の i を、K の p 割る T に選ぶ、という教科書的な目安があります。T は、フェーズ5-1 の2-3節の速度の時定数、10.7秒です。K の p が0.5 なら、K の i は0.5 割る10.7 で約0.047 で、ループ全体が約1秒の時定数で目標へ近づく計算になります。この選び方の理由は、古典制御の間章の3-2節で扱います。この目安は、内部モデル制御、IMC、つまりプラントのモデルから制御器を組み立てる設計の方法にもとづく、PI の調整の決まりの、一次遅れのプラントの場合にあたります。文献は、11節の参考資料にあります。

ただし、この目安は、ペダルが範囲の端、プラスマイナス1 に達しないことが前提です。目標を0 から毎秒10メートルへ一気に上げると、偏差10 に K の p の0.5 を掛けた5 は、上限の1 を大きく超え、しばらくペダルは全開に張り付きます。その間は、目安を求めた式が成り立ちません。4節のシミュレーションで確かめると、K の i が0.047 では、目標のプラスマイナス2パーセントに収まるまでに、約24秒かかりました。2-5節のとおり、ペダルが張り付いている間は積分を止めるので、張り付きが終わった後、積分の項が必要な0.54 まで育つのに時間がかかるのです。そこで、この手順書では、K の i を約2倍の0.1 にして、約14秒で収まるようにしました。

このように、式で目安を立て、シミュレーションで確かめて調整するのが、ゲインを決めるふつうの流れです。

### 2-4. アクセルとブレーキで、ループの速さが変わる

ブレーキは、踏み切ったときの力、9000ニュートンが、アクセルの3000ニュートンの3倍あるので、同じゲインでも、減速するときは、ループが約3倍強く、つまり速く効きます。

さらに、実際には、アクセルの0.5秒とブレーキの0.2秒の遅れがあります。ループが速く効くほど、この遅れの間に行き過ぎやすくなります。ゲインを上げすぎると、ブレーキで減速しすぎてアクセルを踏み直し、また行き過ぎる、という振動が起きます。4-2節の後半の表の最後の行、つまり kp が5.0、ki が2.0 の場合と、6-2節の最後の課題1で、ノードでも確かめます。アクセルとブレーキで時定数が違うこと、つまりフェーズ5-1 の2-2節が、ここで効いてきます。約3倍を式で確かめる方法は、古典制御の間章の3-3節で扱います。

### 2-5. 積分の飽和、ワインドアップと対策

ペダルが上限の1 に張り付いている間も積分を続けると、積分の項が、必要以上に大きく育ちます。目標に達した後も、その育ちすぎた積分が残っているので、ペダルを戻すのが遅れ、目標を大きく行き過ぎます。これを積分の飽和、ワインドアップと呼びます。4節で確かめると、目標の毎秒10メートルに対して、14メートルまで行き過ぎます。

対策、つまりアンチワインドアップには、いくつかの方法があります。この手順書では、いちばん単純な、出力が範囲の端に張り付いていて、偏差がさらに外へ押す向きのときは、積分を足さない、という方法を使います。ペダルが全開の1 で、なお目標より遅い、つまり e が正のときは、積分を止めます。偏差の向きが変われば、つまり目標を追い越しそうになれば、また積分を始めます。

### 2-6. パラメータと既定値

4列の表で、4行あります。列は、パラメータ名、記号、既定値、意味です。

kp は K の p で、既定値は0.5 です。比例ゲインで、偏差が毎秒1メートルあたりの、ペダルの踏み込みです。

ki は K の i で、既定値は0.1 です。積分ゲインで、偏差が毎秒1メートルのまま1秒続いたときに、積分の項が増える量です。

anti_windup は、記号は無く、既定値は true です。アンチワインドアップを使うかどうかです。

period は デルタ t で、既定値は0.02 です。制御の周期、秒で、プラントの周期、0.01秒の2倍です。

制御の周期をプラントより長くしているのは、実物の制御器が、計算やセンサーの都合で、物理の変化よりも粗い間隔でしか動けないことを、まねたものです。

## 3. 仕様

パッケージの learn_py に、ファイルを3つ足します。表は2列で、3行あります。

pi_control.py は、2節の式を計算するクラス PIController です。ROS2 を使いません。

closed_loop_sim.py は、PIController と、フェーズ5-1 の VehicleModel をつないで計算する、ROS2 を使わないシミュレーションです。

pi_node.py は、PIController を包むノード pi_controller で、実行ファイル名も pi_controller です。

pi_controller の仕様は4つです。

受けるのは、/target_velocity と /plant/velocity です。/target_velocity は std_msgs の msg の Float64 で、単位は毎秒メートル、届くまでは0 です。/plant/velocity は、フェーズ5-1 の vehicle_plant が送る現在の速度です。

送るのは /plant/pedal で、型は Float64、マイナス1 から1 の値を、period 秒ごとに送ります。現在の速度が1回も届いていない間は、送りません。

パラメータは、2-6節の表の4つです。実行中に ros2 param set で変えられます。kp と ki は0 以上、period は正の値だけを受け付けます。

ログは、1秒に1回、目標、現在の速度、ペダル、積分の項を出します。

目標の速度は、パラメータではなく、トピックで受け取ります。目標は、実行中に次々と変わる入力で、フェーズ5-3 では、目標の速度を送るノードに置き換えるためです。フェーズ3-3 の6節では、目標の速度もパラメータにする予定と書きましたが、この理由でトピックに変えた、とあります。

主な API、つまりこれまでの手順書で使ったもの以外の API はありません。フェーズ3-1 の Publisher、Subscription、タイマー、フェーズ3-3 のパラメータと変更のコールバック、フェーズ5-1 の、ROS2 を使わないクラスをノードで包む形、の組み合わせです。

## 4. ROS2 なしで閉ループを確かめる

### 4-1. PI 制御器のクラス、pi_control.py

サンプルは、learn_py の learn_py フォルダの pi_control.py です。

pi_control.py は、20行ほどのコードで、PIController のクラスが1つだけあり、ブロックは __init__ と update の2つです。__init__ の出力の範囲の既定は、マイナス1.0 から1.0、anti_windup の既定は True です。要の行は update の中の2つです。new_integral を、今の integral に、ki と偏差と dt を掛けたものを足して求める行と、anti_windup が有効で、出力が張り付いているときは integral を更新しない、という if の行です。

原文の解説の要点です。

__init__ は、ゲイン、出力の範囲、アンチワインドアップを使うかどうかを受け取ります。状態は、積分の項の integral の1つだけです。

update は、2-1節の式を、そのまま1ステップ分のコードにしたものです。new_integral は、今回の偏差を足したと仮定した積分の項です。それを使った出力が範囲を超え、しかも偏差がさらに外へ押す向き、つまり saturated_high か saturated_low なら、積分を足さずに元の値のままにします。これが2-5節のアンチワインドアップです。最後に、範囲の端にそろえた出力を返します。

積分の項に、K の i を掛けてから足している理由も説明されています。integral には、偏差の積分ではなく、K の i かける偏差の積分、つまり積分の項そのものを持たせています。こうしておくと、実行中に K の i を変えても、それまでに育った積分の項は変わらず、ペダルが急に跳ねません。6-2節で、実行中にゲインを変えるときに効いてきます。偏差の積分を持たせて、毎回 K の i を掛ける書き方だと、K の i を2倍にした瞬間に、積分の項も2倍になります。

### 4-2. 閉ループのシミュレーション、closed_loop_sim.py

サンプルは、learn_py の learn_py フォルダの closed_loop_sim.py です。

closed_loop_sim.py は、55行ほどのコードで、ブロックは5つです。1つ目は import で、learn_py の pi_control から PIController を、learn_py の vehicle_model から VehicleModel と VehicleParams を読み込み、プラントの刻み幅の0.01秒と、制御の周期の0.02秒を定数にします。2つ目は target_at の関数で、時刻が40秒より前なら10.0、後なら5.0 を目標として返します。

3つ目は simulate の関数で、計算する長さの既定は70秒です。要の行は、制御の周期に当たるステップでだけ、目標と今の速度の差を制御器の update に渡してペダルを決める行です。

4つ目は main で、後半で比べる5つの場合を、cases という一覧に並べています。既定の PI、P だけ、アンチワインドアップなし、ブレーキの時定数を1.0 にしたもの、kp を5.0、ki を2.0 にしたもの、の5つです。5つ目は、直接実行したときだけ main を呼ぶ、if __name__ の2行です。

原文の解説の要点です。

simulate は、プラントを0.01秒ごと、制御器を0.02秒ごと、つまりプラントの2ステップに1回進めます。制御器は、今の速度から偏差を求めてペダルを決め、次の制御までの間、プラントは同じペダルで進みます。6節でノードをつないだときと同じ周期の関係を、ROS2 なしで再現しています。

main は、前半で、既定のゲインでの時間の変化を表示します。後半で、ゲインや条件を変えた5つの場合について、0秒から40秒の間の最高の速度、40秒の速度、40秒から70秒の間の最低の速度、70秒の速度、の4つを並べます。目標は0秒から毎秒10メートル、40秒から5メートルなので、最高の速度が10 を超えていれば行き過ぎ、最低の速度が5 を下回っていれば、減速のしすぎです。

import は、learn_py の pi_control から、のように、パッケージの名前から読み込んでいます。フェーズ5-1 の vehicle_model.py のように、ファイルを直接 python3 で実行すると、learn_py という名前が見つかりません。そのため、ビルドして source した後に、python3 の -m、つまりモジュールの名前で実行する形で動かします。

python3 の -m で動かすだけなら、setup.py に登録しなくてかまいません。4-1節と4-2節のファイルを置いて、ここでビルドすれば動きます。ノードの実行ファイルとしての登録は、5-3節で行います。

ros2_ws に移って、colcon build に --symlink-install と --packages-select learn_py を付けてビルドし、source install/setup.bash をしてから、python3 の -m で learn_py.closed_loop_sim を実行します。

期待する結果です。ビルドは、learn_py が終わった、という行と、1つのパッケージが終わった、という要約が出れば成功です。シミュレーションの表示は、2つの表です。

前半の表は、4列の表で、15行あります。列は、時刻の秒、目標、速度の毎秒メートル、ペダルです。時刻は、0、1、2、5、10、15、20、30、40、41、42、45、50、60、70秒です。原文の読み方に沿って、要点の数値を拾います。

0秒から5秒です。偏差が大きいので、ペダルは全開のプラス1.00 に張り付き、プラントの最大の加速で、速度が上がります。

10秒より後です。ペダルが0.56 から0.54 へ下がり、速度が毎秒10メートルに近づきます。落ち着いたペダルの0.54 は、2-2節で求めた u スターそのものです。積分の項が、毎秒10メートルを保つのに必要な踏み込みを探し当てました。

40秒です。目標が毎秒5メートルに下がると、偏差がマイナス5 になり、ペダルはマイナス1.00、つまりブレーキ全開に張り付きます。ブレーキは強く速いので、約1秒で、毎秒5.74メートルまで下がります。

42秒から50秒です。毎秒5.15メートル前後から、ゆっくり5メートルへ近づきます。毎秒5メートルを保つのに必要なペダルは約0.31 で、積分の項が0.54 から0.31 へ下がるのに時間がかかるためです。偏差が小さいので、積分の項の変わり方も、ゆっくりになります。

後半の表は、5つの場合を、4つの速度で比べた表です。数値は、原文の、後半の表の読み方の表で拾います。3列で、5行です。列は、場合、起きていること、対応する節です。

既定の PI は、行き過ぎも減速のしすぎもなく、毎秒10メートルと5メートルに落ち着きます。

P だけは、9.01 と4.44 で止まり、目標に届きません。2-2節の値と一致します。

アンチワインドアップなしは、14.00 まで行き過ぎます。40秒には、10.01 まで戻っています。2-5節の話です。

ブレーキの時定数を1.0 にしたものは、減速で3.89 まで下がりすぎます。2-4節と6-5節の話です。

kp が5.0、ki が2.0 のものは、減速で4.12 まで下がりすぎます。途中で、ペダルがブレーキ全開とアクセル全開の間で振れます。2-4節の話です。

課題が2つあります。

課題1。main の最初の simulate の ki を0.1 から0.047、つまり2-3節の式の目安の値に変え、10秒、15秒、20秒の速度を、既定のゲインと比べます。張り付きが終わった後の近づき方が、ゆっくりになります。

課題2。P だけの行の kp を1.0 と2.0 に変えると、40秒の速度はいくつになるか、実行して確かめます。古典制御の間章の3-1節の式を使えば、実行する前に予想できます。K の p を大きくするほど10 に近づきますが、届きません。

## 5. ノードで包む

### 5-1. PI 制御のノード、pi_node.py

サンプルは、learn_py の learn_py フォルダの pi_node.py です。

pi_node.py は、90行ほどのコードで、ブロックは6つです。1つ目は import で、rclpy、SetParametersResult、ExternalShutdownException、Node、Float64 と、learn_py の pi_control の PIController を読み込みます。

2つ目は、Node を継承した PIControllerNode のクラスの __init__ で、要の行は、kp を0.5、ki を0.1、anti_windup を True、period を0.02 で宣言する4行と、velocity を None で始める行です。3つ目は on_target と on_velocity、4つ目は on_timer で、要の行は、偏差を制御器の update に周期と一緒に渡して、ペダルを得る行です。5つ目は on_params、6つ目は main です。

原文の解説の要点です。役割は、4-1節の PIController を、トピックとパラメータで ROS2 につなぐことです。フェーズ5-1 の plant_node.py と同じく、式はこのファイルにありません。

クラス名は、ノードのクラスを PIControllerNode とし、式のクラスの PIController と名前を分けています。同じファイルに両方を import しても、取り違えないようにするためです。

__init__ は、4つのパラメータを宣言し、その値で PIController を作ります。anti_windup は、既定値が True なので、パラメータの型は真偽値、bool になります。

on_target と on_velocity は、届いた値を覚えるだけです。計算は on_timer でまとめて行います。フェーズ5-1 の on_pedal と同じ考え方です。velocity を None で始めているのは、プラントの速度が1回も届く前に、速度0 とみなして、ペダルを踏み始めないようにするためです。

on_timer は、偏差を求め、update でペダルを計算して送ります。制御の刻み幅には、フェーズ5-1 の on_timer と同じく、period を使います。

on_params は、フェーズ3-3 の形で、検証してから反映します。ゲインは、PIController の属性を直接書き換えます。積分の項の integral はそのまま残るので、実行中に kp や ki を変えても、制御は途切れずに続きます。4-1節の解説の最後の点のとおりです。

### 5-3. 実行ファイルとして登録し、ビルドする

learn_py の setup.py の entry_points に、1行足します。今ある行は、すべて残します。フェーズ5-1 まで進めた状態なら、console_scripts の一覧には、フェーズ5-1 の gz_display までに足した12個ほどの行があり、その後ろに、pi_controller を learn_py の pi_node の main に結び付ける行を足します。並び順や、任意のページで足した行の有無は、進め方によって違ってかまいません。pi_control.py と closed_loop_sim.py は、実行ファイルとして登録しません。前者はノードから import される部品、後者は python3 の -m で動かすものだからです。

## 6. 動かす

### 6-1. ループを閉じる

ターミナルを3つ使います。ターミナル1 でプラント、ターミナル2 で PI 制御のノードを動かし、ターミナル3 から目標の速度を送ります。3つとも、ros2_ws に移って source install/setup.bash をします。ターミナル1 では ros2 run learn_py vehicle_plant、ターミナル2 では ros2 run learn_py pi_controller を起動し、ターミナル3 では、ros2 topic pub に --once を付けて、/target_velocity に、std_msgs の msg の Float64 で、data を10.0 にした値を送ります。

期待する結果、ターミナル2 の分です。目標の毎秒10メートルを送った前後の抜粋です。時刻は実行ごとに変わり、数値も、目標が届いた時刻とログの時刻のずれで少し変わります。1秒に1行ずつ、目標、速度、ペダル、積分の項が出ます。目標が届いてから6秒ほどは、ペダルがプラス1.00 のまま、積分の項が0.000 のまま、速度が上がっていきます。速度が9 の近くまで上がると、ペダルが全開から下がり、積分の項が増え始めます。最後には、速度が10.00、ペダルが0.54、積分の項が0.540 に落ち着きます。

この結果の読み方が3つあります。

1つ目。目標を送る前は、目標も速度も0 なので、ペダルも0 です。

2つ目。目標の毎秒10メートルが届くと、ペダルはプラス1.00、つまり全開に張り付きます。この間、積分の項は0 のまま増えません。2-5節のアンチワインドアップです。

3つ目。速度が毎秒9メートル近くまで上がると、ペダルが全開から離れ、積分の項が育ち始めます。やがて、速度は10.00 に、ペダルは0.54 に、積分の項は0.540 に落ち着きます。2-2節で求めた u スターの0.54 と一致します。ターミナル1 の vehicle_plant のログも、同じように速度が10 へ近づきます。

期待する結果、ターミナル2 の分です。目標が5 に変わった直後の行で、ペダルがマイナスになり、その1秒後には、速度が5.2 のあたりまで下がっています。最後には、速度が5.00、ペダルが0.31、積分の項が0.307 になります。

読み方が2つあります。1つ目。目標が下がった直後は、ブレーキ、つまりマイナスのペダルを踏み、1秒ほどで毎秒5メートルのあたりまで下がります。5メートルを下回らずに止まっています。2つ目。その後は、毎秒5.1 から5.2メートルのあたりから、ゆっくり5.00 へ近づきます。積分の項が0.54 から0.31 へ下がっていく途中で、4節の表の42秒から50秒と同じ振る舞いです。

続けて、パラメータの検証を確かめます。ターミナル3 で、ros2 param set で /pi_controller の kp をマイナス1.0 にし、ros2 param get で kp を見ます。

期待する結果です。ros2 param set は、失敗した、kp は0 以上でなければならない、と出ます。ros2 param get は、Double の値が0.5 と出ます。負のゲインは拒否され、値は0.5 のままです。

### 6-2. ゲインと条件を変えて比べる

4節の後半の表の3つの場合を、ノードで確かめます。比べやすいように、毎回、止まった状態から始めます。ターミナル1 の vehicle_plant とターミナル2 の pi_controller を Ctrl+C で止め、ターミナル1 は同じコマンドで、ターミナル2 はパラメータを指定して起動し直してから、ターミナル3 で目標の毎秒10メートルを送ります。

1つ目は、P 制御だけ、つまり ki を0 にする場合です。ターミナル2 で、ros2 run learn_py pi_controller に --ros-args と、-p で ki を0.0 にした指定を付けて起動します。

期待する結果、ターミナル2 の分です。目標を送ってから十数秒後より後の抜粋です。速度は9 の少し手前から少し上下したあと、9.01 のままになります。ペダルは0.62 から0.46 の間を動き、0.49 前後に落ち着きます。積分の項は、ずっと0.000 です。

速度は毎秒9.01メートルで止まり、10 に届きません。積分の項は0 のままで、ペダルは0.49、つまり K の p かける偏差、0.5 かける0.99 です。2-2節の値、9.01 と一致します。

実行中に ros2 param set で ki を0.0 にして比べる方法もありますが、それだと、それまでに育った積分の項が残るので、4-1節の解説の最後の点のとおり、P 制御だけの振る舞いにはなりません。起動し直すのは、そのためです。

2つ目は、アンチワインドアップを使わない場合です。ターミナル2 で、ros2 run learn_py pi_controller に、-p で anti_windup を false にした指定を付けて起動します。ターミナル1 の起動し直しと、ターミナル3 の目標の毎秒10メートルは、上と同じです。

期待する結果、ターミナル2 の抜粋です。ペダルが全開のプラス1.00 の間も、積分の項が増え続け、速度が9.61 のときには3.853 まで育ちます。速度は10 を超えても上がり続け、13.44 まではペダルが1.00 のままです。13.96 でペダルが0.65 に下がり、そのあと速度が下がり始め、積分の項も減っていきます。最後には、速度が10.03、ペダルが0.54、積分の項が0.554 になります。

読み方が3つあります。1つ目。ペダルが全開に張り付いている間も、積分の項が増え続け、3.8 まで育ちます。アンチワインドアップがあるときは、0 のままでした。2つ目。そのため、速度が毎秒10メートルを超えても、ペダルは全開のまま戻らず、約14メートルまで行き過ぎます。積分の項が減るまで、ペダルを戻せません。3つ目。その後、ゆっくり10 へ戻ります。4節の表の、アンチワインドアップなしの行の14.00 と一致します。

課題が2つあります。

課題1。ros2 run learn_py pi_controller に、-p で kp を5.0、-p で ki を2.0 にして起動し、目標の毎秒10メートルから5メートルを送ります。4-2節の後半の表の最後の行のとおり、減速で4メートル前後まで下がりすぎ、ターミナル2 のログで、ペダルがブレーキ全開のマイナス1.00 と、アクセル全開のプラス1.00 の間で振れる様子を見ます。

課題2。既定のゲインで動かしたまま、ros2 param set で /pi_controller の kp を1.0 にして、目標を毎秒10メートルと5メートルの間で何度か切り替え、既定の0.5 のときと、追いつく速さを比べます。実行中にゲインを変えても、ペダルが跳ねないことも、ターミナル2 のログで確かめます。

### 6-3. YAML でゲインを渡し、調整した結果を残す

ゲインの組み合わせは、フェーズ3-3 の5-4節のとおり、YAML のファイルにまとめておくと、何度でも同じ条件で試せます。ros2_ws の config に、pi_controller.yaml を作ります。ros2_ws の config は、フェーズ3-3 で作ったフォルダです。フェーズ4 の3-1節で空になって消した場合は、mkdir -p で作り直します。フェーズ4 を済ませていれば、learn_bringup の config に置いてもかまいません。フェーズ5-3 では、そちらを使います。

ターミナル2 の pi_controller を止めて、ros2 run learn_py pi_controller に、--ros-args と、--params-file でこの YAML のパスを渡して、起動し直します。ターミナル3 で、ros2 param get で kp を見て、ros2 param dump で /pi_controller のパラメータを全部書き出します。

期待する結果です。ros2 param get は、Double の値が0.8 と出ます。ros2 param dump は、/pi_controller の ros__parameters の下に、anti_windup が true、ki が0.15、kp が0.8、period が0.02 と、ノードが自動で持つ2つのパラメータ、start_type_description_service が true、use_sim_time が false を、名前の順に表示します。

### 6-4. Gazebo で見る

### 6-5. 時定数を変えて、同じゲインで比べる

同じゲイン、つまり既定の0.5 と0.1 のまま、プラントのブレーキの時定数を0.2秒から1.0秒に変えて、目標の毎秒10メートルから5メートルを試します。ターミナル1 の vehicle_plant を起動し直すときに、時定数を指定します。ターミナル2 も起動し直して、止まった状態から始めます。

ターミナル1 では、ros2 run learn_py vehicle_plant に、--ros-args と、-p で tau_brake を1.0 にした指定を付けて起動します。ターミナル2 では、ros2 run learn_py pi_controller を起動します。ターミナル3 では、目標の毎秒10メートルを送り、速度が10 に落ち着いてから、つまり30秒ほど後に、目標の5メートルを送ります。

期待する結果、ターミナル2 の分です。目標が5 に変わった最初の行で、ペダルがマイナス1.00 になります。2秒ほどで、速度は3.87 まで下がり、ペダルがプラス1.00 になります。そのあと、速度は5.41 まで、5 を超えて戻り、最後には、速度が5.02、ペダルが0.31 になります。

読み方が3つあります。

1つ目。目標が下がると、ブレーキ全開のマイナス1.00 を踏みますが、ブレーキの力が立ち上がるのに時間がかかるので、制御器は、まだ減速が足りない、と踏み続けます。力が遅れて効いてくると、今度は減速しすぎて、毎秒3.87メートルまで下がります。

2つ目。下がりすぎたので、アクセル全開のプラス1.00 を踏み直し、5.41 まで戻りすぎてから、5 へ落ち着きます。

3つ目。既定の時定数、0.2秒では、5 を下回らなかったのに対し、同じゲインでも、プラントの時定数が変わると、追いつき方が悪くなります。4節の表の、ブレーキの時定数を1.0 にした行の3.89 と一致します。

終わったら、ターミナル1 を起動し直して、時定数を既定値に戻します。

## 7. フィジカル AI へのつながり、時定数とゲイン

6-5節で、プラントの時定数が変わると、同じゲインでは追いつき方が悪くなることを確かめました。フェーズ5-1 の7節で書いたとおり、実物の車両やロボットのアクチュエータの遅れ方は、すり減り、温度、荷物、個体差で変わります。ある時定数に合わせて調整したゲインは、別の時定数では最適ではありません。

フェーズ6 の後の、最終のゴールに向かうフェーズ7、つまり元のアイデアのステップ6 では、PI のゲインの調整を、強化学習のエージェントに任せます。ブレーキの時定数を1.0秒にしたプラントで、手で決めた既定のゲインに代わるゲインを、試行錯誤から探させます。これはフェーズ7-2 の手順書です。さらに、PI 制御そのものをニューラルネットワーク、NN に置き換えて、PI 制御と比べます。これはフェーズ7-4 の手順書です。この手順書の部品は、そのための道具にもなります。部品の役立ち方は3つです。

1つ目。closed_loop_sim.py のように、ROS2 を使わずに閉ループを計算できれば、1回の試行が一瞬で終わります。学習のために何千回も試すときは、この速さが効きます。フェーズ7-1 の環境は、この計算と同じ形で作ります。

2つ目。pi_controller のゲインは、実行中に ros2 param set で変えられるので、ROS2 の上で動かしたまま、外から、つまり AI から、ゲインを差し替えられます。4-1節のとおり、積分の項を持たせる形にしてあるので、差し替えても、ペダルが跳ねません。任意のフェーズ7-2 の、ゲインを選ぶ環境も、ゲインを差し替えるときに、この性質を使います。

3つ目。追いつき方の良し悪しは、4節の表のように、行き過ぎ、下がりすぎ、落ち着いた速度、などの数で表せます。強化学習では、このような数から、報酬を作ります。

フェーズ5-4 では、プラントの時定数ではなく、車体そのもの、つまり質量と抵抗を Gazebo の物理に差し替えて、同じゲインで比べます。自作の式で決めたゲインが、より現実に近いシミュレーションではどう効くか、という、シミュレーションと現実の差の問題にもつながります。

## 8. このフェーズのまとめ

まとめは6つです。

1つ目。PI 制御は、偏差に比例して踏む項と、偏差の積分で踏み増す項の和で、ペダルを決めます。

2つ目。P 制御だけでは、速度を保つのに踏み込みが要る分だけ、偏差が残ります。K の p が0.5 なら、目標の毎秒10メートルに対して9.01メートルです。積分の項は、必要な踏み込み、つまり0.54 を自分で探し当て、偏差を0 にします。

3つ目。ゲインは、式で目安を立て、その求め方は古典制御の間章の3-2節にありますが、ペダルが張り付く範囲では式が成り立たないので、シミュレーションで確かめて調整します。

4つ目。ペダルが上限に張り付いている間の積分は、行き過ぎの原因になります。これがワインドアップです。張り付いている間は積分を止めます。これがアンチワインドアップです。

5つ目。アクセルとブレーキで、力の大きさと遅れが違うので、同じゲインでも、加速と減速で効き方が違い、時定数が変わると、追いつき方が悪くなります。

6つ目。制御の式も ROS2 を使わないクラスに分けたので、プラントのクラスとつないで、ROS2 なしで閉ループを計算できます。

## 9. つまずきやすい点

2列の表で、7行あります。列は、症状と、確かめることです。

1行目。python3 の -m で learn_py.closed_loop_sim を実行して、learn_py という名前のモジュールが無い、と出る場合。ビルドして source install/setup.bash をしたか、python3 にファイルのパスを渡して直接実行していないかを確かめます。4-2節の解説のとおりです。

2行目。pi_controller のログが出ない場合。vehicle_plant が動いているかを確かめます。現在の速度が1回も届かない間は、何も計算しません。5-1節の解説のとおりです。

3行目。目標を送っても、速度が上がらない場合。トピック名の /target_velocity と、型のつづりを確かめます。ターミナル2 のログの target が変わっているかも見ます。

4行目。P 制御にしたのに、偏差が残らない場合。実行中に ki を0 にしています。積分の項が残っているので、起動し直します。6-2節のとおりです。

5行目。車両が止まらない、加速し続ける場合。pi_controller を先に止めています。プラントは、最後のペダルを踏み続けます。ターミナル3 で、ros2 topic pub に --once を付けて、/plant/pedal に data がマイナス1.0 の Float64 を送ってから、vehicle_plant を止めます。

6行目。ペダルがマイナス1 とプラス1 の間で振れる場合。ゲインが大きすぎます。2-4節と、6-2節の最後の課題1のとおりです。kp と ki を下げます。

7行目。ros2 param set で kp を1 にすると失敗する場合。整数を渡しています。1.0 と書きます。フェーズ3-3 の5-3節のとおりです。
