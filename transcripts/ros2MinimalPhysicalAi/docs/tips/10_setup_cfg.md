# Tips集 10: setup.cfg の役割、この教材では編集しない（聞くための原稿）

これは、ros2MinimalPhysicalAi という教材の、Tips集の10個目の項目です。

Tips集は、手順書、つまりフェーズの本文に入れると流れが途切れる、分量の少ない補足をまとめた資料です。どの項目も独立しているので、関係する手順書を読んでいるときや、疑問を持ったときに、その項目だけを読めばよい、とあります。

対象は、ROS2 Jazzy と Ubuntu 24.04 です。版に依存する記述は、この資料を作ったときに、/opt/ros/jazzy と Ubuntu のパッケージに入っていたもので確かめた、とあります。所要の目安は、1項目あたり5 から15分の読み物です。

この項目に関係する手順書は、Python のパッケージを扱う、フェーズ2 の1-3節、2-2節、2-6節です。

出どころについて、断りがあります。この資料の内容は、/opt/ros/jazzy のソースや、ros2 pkg create が作る雛形、Ubuntu のパッケージの colcon-core と setuptools などを読んで確かめ、自分の言葉で書いたもので、ソースやドキュメントの転載ではない、とあります。10節は、/opt/ros/jazzy の ros2pkg の雛形などのソースを読み、使い捨てのワークスペースで確かめた、とあります。確かめたのは、setup.cfg を雛形のままにした場合、消した場合、パッケージの名前を変えて、setup.cfg の中の名前だけを古いままにした場合、ハイフンでつないだ名前で書いた場合の4通りで、ビルドと、ros2 pkg executables と ros2 run の表示を見た、とあります。2026年10月15日のことです。何をどう確かめたかの細かな点は、本文の中で述べています。

この原稿では、setup.cfg の中身と、警告の文面を書き写さずに、何が書かれているかを言葉で説明します。

## 10. setup.cfg の役割、この教材では編集しない

読める時期について、囲みがあります。フェーズ2 の2-6節で、install のフォルダの中身を見た後に読めます。つまり、2-2節で Python のパッケージを作り、2-4節でビルドし、2-5節で ros2 run を使った後です。

### 10-1. 疑問: 一度も編集しないファイルは、何のためにあるのか

ros2 pkg create に、マイナス2つの build-type で ament_python を指定して作ったパッケージには、setup.py と並んで、setup.cfg があります。この教材では、ノードを足すときは setup.py の entry_points を、依存を足すときは package.xml を書き換えますが、setup.cfg は、どのフェーズでも作られたまま使い、一度も編集しません。

それでも、このファイルを消した状態で一からビルドすると、ビルドは成功するのに、ros2 run でノードを起動できなくなります。この節では、このファイルが何をしているのかと、編集が要るのはどんな場面かをまとめます。

### 10-2. 雛形の中身

フェーズ2 の learn_py の場合、雛形の setup.cfg の中身は4行です。ros2 pkg create が作ったままで、書き換えないので、写す必要はない、とあります。

4行は、2つの見出しと、それぞれの下の1行です。1つ目の見出しは develop で、その下に script_dir の行があります。2つ目の見出しは install で、その下に install_scripts の行があります。どちらの値も、ドル記号の base の後に、lib の learn_py をつなげたものです。

setup.cfg は、setup.py を実行したときに、setuptools が読みに行く設定ファイルです。setuptools については、Tips集の3-1節にあります。角かっこで囲んだ見出しは、setuptools のコマンドの名前で、その下に、そのコマンドの設定を書きます。

3つの点があります。

1つ目。develop の見出しは、colcon build にマイナス2つの symlink-install を付けたときに、colcon が実行する、setup.py の develop というコマンドの設定です。

2つ目。install の見出しは、マイナス2つの symlink-install を付けないときに、colcon が実行する、setup.py の install というコマンドの設定です。

3つ目。ドル記号の base は、インストール先の根元、つまり、このパッケージの install の下の learn_py のフォルダに置き換わります。

つまり、2つの見出しは、どちらのビルドの仕方でも、entry_points の console_scripts で作られる実行ファイルを、install の下の、learn_py の lib の learn_py のフォルダに置く、という同じことを言っています。パッケージの名前が2か所に入っているのは、ros2 pkg create が作るときに、指定したパッケージ名を埋め込んだためです。

### 10-3. なぜ要るのか: ros2 run が探す場所

ros2 run に、パッケージ名と実行ファイル名を渡すと、パッケージのインストール先の、lib の下の、パッケージ名のフォルダの中だけを探します。/opt/ros/jazzy の ros2pkg のソースで確かめた、とあります。

C++ のパッケージでは、install の命令に TARGETS と DESTINATION を指定した、install(TARGETS ...) の行が、実行ファイルをこの場所に置きます。置き場所は、lib の下の、ドル記号と中かっこで PROJECT_NAME を囲んだものです。Tips集の2-2節の表の、install(TARGETS ...) の行のことです。Python のパッケージで、同じ場所に置かせているのが、setup.cfg です。

setup.cfg が無いと、setuptools は実行ファイルを、Python の道具の既定の置き場所の、bin のフォルダに置きます。

この資料を作ったときに、使い捨てのワークスペースで、雛形のパッケージを colcon build し、ros2 pkg executables にパッケージ名を渡して確かめた、とあります。雛形のパッケージは、マイナス2つの node-name で、実行ファイルを1つ登録したものです。ros2 pkg executables は、ros2 run で起動できる実行ファイルの一覧を表示するコマンドです。

結果の表は5列で2行です。列は、setup.cfg、ビルドの仕方、ビルド、実行ファイルの場所、ros2 pkg executables です。

1行目は、setup.cfg が雛形のままの場合です。ビルドの仕方は、マイナス2つの symlink-install の、ありとなしの両方です。ビルドは成功します。実行ファイルの場所は、install の下の、パッケージ名の lib の、パッケージ名のフォルダです。ros2 pkg executables には、表示されます。

2行目は、setup.cfg を消した場合です。ビルドの仕方は、同じく、ありとなしの両方です。ビルドは成功します。実行ファイルの場所は、install の下の、パッケージ名の bin のフォルダです。ros2 pkg executables には、何も表示されません。

setup.cfg を消しても、ビルドは成功するので、ビルドの表示だけでは気づけません。ros2 run を実行して初めて、1行だけが表示されて終わります。その1行は、No executable found、つまり、実行ファイルが見つからない、という表示です。この表示は、10-4節の、名前を古いままにした場合に、実際に確かめたもの、とあります。消した場合も、ros2 pkg executables に何も表示されないので、同じ表示になる、とあります。

ただし、これは一から作ったワークスペースの場合です。colcon は、ビルドし直しても、install のフォルダの古いファイルを消しません。前のビルドの実行ファイルが、install の下の、パッケージ名の lib の、パッケージ名のフォルダに残っていると、setup.cfg を消した後も、ros2 run は、その古い実行ファイルを起動します。確かめるときは、そのパッケージの、build の下のパッケージ名のフォルダと、install の下のパッケージ名のフォルダを消してから、ビルドします。

補足があります。colcon は、install の見出しの install_scripts の値を、自分で読み、setup.py の install に、マイナス2つの install-scripts という引数としても渡しています。Python の仮想環境の中では、setuptools が、設定ファイルのこの項目を無視するためです。Ubuntu 24.04 の、colcon-core 0.21.3 のソースのコメントで確かめた、とあります。どちらの経路も、setup.cfg の同じ値を使うので、実行ファイルの置き場所は変わりません。この教材の ROS2 は、仮想環境の中では動かさないので、読み流してよい、とあります。

### 10-4. 編集が要る場面

この教材のように、ros2 pkg create で作ったパッケージに、ノード、依存、データのファイルを足していくだけなら、setup.cfg を編集する場面はありません。

足すものごとの書き換え先の表は、2列で3行です。列は、足すものと、書き換えるファイルです。

1行目は、ノード、つまり実行ファイルです。書き換えるのは、setup.py の entry_points の console_scripts です。

2行目は、依存するパッケージです。書き換えるのは package.xml で、Python のライブラリなら、setup.py の install_requires も書き換えます。

3行目は、launch ファイルや YAML などのデータです。書き換えるのは、setup.py の data_files です。ただし、この教材では、Python のパッケージにはデータを置かず、ament_cmake の learn_bringup にまとめています。フェーズ4 の3-3節です。

編集が要るのは、2つの場面です。

1つ目は、パッケージの名前を変えたときです。パッケージの名前は、多くの場所に入っています。package.xml の name の要素、setup.py の package_name、entry_points のモジュール名、resource のフォルダの目印のファイル名、内側のモジュールのフォルダ名、そして setup.cfg の2か所です。entry_points のモジュール名とは、learn_py の hello の main を指す書き方の、先頭の learn_py のことです。目印のファイルは、resource のフォルダの learn_py という名前のファイル、内側のフォルダは、learn_py の中の learn_py のフォルダです。

setup.cfg だけを直し忘れても、ビルドは成功します。しかし、実行ファイルは、install の下の、新しい名前の lib の、古い名前のフォルダに入るので、ros2 run に新しい名前と実行ファイル名を渡すと、No executable found で終わります。この資料を作ったときに、使い捨てのワークスペースで確かめた、とあります。ros2 pkg create を新しい名前でやり直し、コードを写すほうが、直し忘れが起きにくい、とあります。

2つ目は、古い版向けのパッケージを使うときです。古い記事や、古い ROS2 の版の雛形から作ったパッケージには、script-dir や install-scripts のように、ハイフンでつないだ名前で書かれているものがあります。Ubuntu 24.04 の setuptools、つまり版 68.1.2 では、実行ファイルは正しい場所に入りますが、ビルドのたびに、非推奨の警告が出ます。非推奨の警告については、Tips集の3節にあります。この資料を作ったときに、使い捨てのワークスペースで表示させたもの、とあります。

警告は3行です。1行目は、警告の種類の名前の SetuptoolsDeprecationWarning と、見出しです。2行目と3行目が、本文です。内容は、ハイフンでつないだ設定の名前は無効で、script-dir は将来の版では使えなくなるので、アンダースコアの名前の script_dir を使ってください、というものです。警告の文面のとおり、アンダースコアでつないだ名前、つまり script_dir と install_scripts に書き換えます。

setup.cfg には、ほかにも、パッケージの名前や依存などの、setuptools の設定を書くことができます。ただし、ROS2 の雛形では、それらを setup.py に書いているので、setup.cfg には、上の2つの見出しだけを置いておけばよい、とあります。
