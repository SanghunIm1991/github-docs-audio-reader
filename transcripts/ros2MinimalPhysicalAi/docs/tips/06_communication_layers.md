# Tips集 6: ROS2 の通信の層を詳しく（聞くための原稿）

項目の一覧では、この項目は、ROS2 の通信の層を詳しく、つまり DDS、RMW、ディスカバリ、QoS、と書かれています。関係する手順書は、フェーズ0 の2節です。

出どころについて、断りがあります。この資料の内容は、/opt/ros/jazzy のソースなどを読んで確かめ、自分の言葉で書いたもので、ソースやドキュメントの転載ではない、とあります。6節は、フェーズ0 の本文から移したもので、ROS2 と DDS の公式ページの記載に基づいて書いた、とあります。ページのアドレスは、フェーズ0 の10節にあります。6節の RMW の導入の状況、つまり ROS2 と一緒に入るもの、apt にあるパッケージ、依存関係に製品本体が含まれるかは、この資料を作ったときに、/opt/ros/jazzy と apt のパッケージの情報で確かめた、とあります。

## 6. ROS2 の通信の層を詳しく

フェーズ0 の2節では、ROS2 の通信が、層を積み重ねた構造、つまりプロトコルスタックになっていることだけを説明しました。ここでは、その図に出てきた各層と、関係する仕組みの名前を補います。取り上げるのは4つです。

1つ目は、DDS、Data Distribution Service です。OMG、つまり Object Management Group という標準化団体が定めた、分散型の publish と subscribe の通信の規格です。ROS2 は、この DDS、正確には、その通信規約の DDS/RTPS を、標準の通信層として使っています。

2つ目は、RMW、ROS Middleware Interface です。ROS2 の API と、DDS の実装の製品をつなぐ層です。この層のおかげで、ROS2 のコードを変えずに、DDS の実装を差し替えられます。

ROS2 と一緒に入るのは、既定の Fast DDS 向けの RMW、つまり rmw_fastrtps_cpp だけです。ROS2 の apt のリポジトリには、Cyclone DDS、RTI Connext、GurumDDS 向けの RMW のパッケージもあり、使う実装のパッケージを別に導入してから、環境変数の RMW_IMPLEMENTATION で切り替えます。RTI Connext と GurumDDS は企業の商用の製品で、使う条件、つまりライセンスは、提供元が定めています。特に Connext は、RMW のパッケージを入れただけでは動かず、製品の本体も別に導入する必要があります。

3つ目は、ディスカバリ、つまり自動発見です。各ノードは起動すると、マルチキャストでお互いを見つけ合います。同じネットワークにある別のシステムと混ざらないよう、ROS_DOMAIN_ID、つまりドメイン ID の番号で、通信の範囲を分けます。見つけた相手と何を確かめ合っているかは、Tips集の4節で説明しています。

4つ目は、QoS、Quality of Service です。トピックごとに、次のようなことを決められます。信頼性の reliability は、送りっぱなしか、確実に届けるかです。持続性の durability は、後から参加した購読側に、過去のデータを渡すかです。履歴の history は、直近の何件を手元に残すかです。ほかにもあります。配信側と購読側の QoS がかみ合わないと、つながりません。つながるかどうかは、購読側が求める水準を、配信側が満たしているかで決まります。実際に試すのは、フェーズ3-2b です。
