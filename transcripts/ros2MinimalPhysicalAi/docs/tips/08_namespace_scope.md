## 8. 名前空間、namespace が効く範囲

### 8-1. 疑問: 名前空間を付けても変わらない、とは、どこの話か

フェーズ3-2a の4節では、/turtle1/cmd_vel のように、先頭にスラッシュを付けたトピック名は、ノードに名前空間を付けて起動しても、組み立てられるトピック名が変わらない、と書いています。これは、ノードの中でトピック名を組み立てるときの話です。

名前空間は、ノードに付く属性です。ノードが Publisher や Subscriber を作るとき、渡されたトピック名が相対名、つまり先頭にスラッシュが無い名前なら、ノードの名前空間を前に付けて、完全な名前にします。絶対名、つまり先頭がスラッシュなら、そのまま使います。この組み立ては、ノードの中、つまり ROS2 のクライアントライブラリで済んでしまいます。

トピック通信の側が扱うのは、組み立て終わった完全な名前だけです。/demo/chatter は、demo という区画の中の chatter ではなく、単に /demo/chatter という1つの長い名前として扱われます。だから、名前空間は、通信を仕切る壁ではありません。名前空間が違うノード同士でも、完全な名前が同じなら、つながります。通信の範囲そのものを分けたい場合は、名前空間ではなく、ROS_DOMAIN_ID を使います。これは Tips集の6節で扱っています。

### 8-2. 名前の3つの書き方

ノードの名前空間が /demo、ノード名が talker のとき、トピック名は、次のように組み立てられます。

表は3列で3行です。列は、書き方と、例と、完全な名前です。

1行目は、絶対名です。例は /chatter で、完全な名前も /chatter です。名前空間は付きません。

2行目は、相対名です。例は chatter で、完全な名前は /demo/chatter です。

3行目は、プライベート名です。例は、チルダとスラッシュの後に chatter と書くもので、完全な名前は /demo/talker/chatter です。ノードの完全な名前の下に付きます。

名前空間は、起動するときに、外から付けられます。ros2 run なら、マイナス2つの ros-args の後に、マイナス r と、アンダースコア2つの ns、コロンとイコール、/demo と続けます。launch なら PushRosNamespace で、フェーズ4 の4-6節で扱っています。コードの側は、相対名で書いておけば、付けられた名前空間に従います。

### 8-3. 名前空間を意識しなければならない場面

4つの場面があります。

1つ目は、同じノードを複数動かすときです。ロボットを2台動かすなら、それぞれのノードを、/robot1 と /robot2 の名前空間で起動し、/robot1/cmd_vel と /robot2/cmd_vel に分けるのが、ふつうのやり方です。turtlesim の /turtle1/cmd_vel と /turtle2/cmd_vel も、同じ発想で分かれています。これは、フェーズ1 の3-5節で、/spawn で2匹目を出したときに増えるトピックです。このとき、コードの中のトピック名が絶対名だと、名前空間を付けても、全員が同じトピックに集まり、指令が混ざります。複数動かす前提のノードは、相対名で書きます。

2つ目は、名前空間の違う相手とつなぐときです。フェーズ3-2a の turtle_circle は、相手の turtlesim が待っている /turtle1/cmd_vel に確実に届けるため、絶対名で書いています。ところが、こう書いたノードは、名前空間を付けるだけでは送り先が変わらないので、ロボットごとに名前空間で分ける使い方ができません。別の亀やロボットに向け直すには、remap、つまりトピック名の付け替えを使います。フェーズ4 の4-6節で扱っていて、remap は絶対名にも効きます。複数台で使い回す前提なら、相対名で書いておくと、名前空間を付けるだけで分けられます。どちらにしても、つながるかどうかは、両側の完全な名前が一致するかで決まります。

3つ目は、コマンドから触るときです。ros2 topic echo や ros2 param get などは、完全な名前で指定します。例えば、ros2 param get /demo/talker use_sim_time のようにします。ros2 topic pub に、相対名の chatter を渡すように書くと、コマンドの側は名前空間の外、つまりスラッシュだけの場所にいるので、/chatter に送ってしまい、/demo/chatter を待つノードには届きません。ros2 topic list で完全な名前を確かめてから指定するとよい、とあります。

4つ目は、パラメータの YAML のファイルを渡すときです。この段落と8-4節は、パラメータを YAML のファイルで渡す方法、つまりフェーズ3-3 の5-4節を読んだ後のほうが分かりやすい、とあります。YAML の先頭に書くノード名は、名前空間を含めた完全な名前と照らし合わされます。talker、コロン、と書いたファイルは、名前空間の無い /talker にしか効きません。名前空間を付けて起動したノードには、/demo/talker、コロン、のように名前空間まで書くか、すべてのノードに当てはまる、スラッシュとアスタリスク2つを使います。この違いはエラーにならず、値が黙って既定値のままになるので、気づきにくい、とあります。

### 8-4. 確かめる: YAML のノード名と名前空間

ROS2 に付属するデモの talker、つまり demo_nodes_cpp の talker を、名前空間 /demo で起動し、use_sim_time を true にする YAML を渡します。ノード名の書き方だけが違う、3つのファイルを用意します。ここでは、確かめるためだけのフォルダ、ホームの yaml_check に置き、T1 はそのフォルダで実行します。ほかの場所に置いても構いません。別の場所から実行する場合は、マイナス2つの params-file に、絶対パスで渡します。

まず、mkdir マイナス p で、ホームの yaml_check を作ります。

期待する結果です。何も表示されません。すでにあるフォルダでも、エラーになりません。

ファイルは3つで、どれも、ホームの yaml_check に置きます。3つとも同じ形で、ノード名の行の下に ros__parameters の段があり、その下に、use_sim_time を true にする行があります。違うのは、ノード名の行だけです。talker.yaml では talker、demo_talker.yaml では /demo/talker、all.yaml では、スラッシュとアスタリスク2つです。

T1 で1つ目のファイルを渡して起動し、T2 で確かめます。確かめたら、T1 を Ctrl+C で止め、残りのファイルでも、同じことを繰り返します。

コマンドは、T1 が2つ、T2 が2つです。T1 では、cd でホームの yaml_check に移動し、ros2 run demo_nodes_cpp talker に、8-2節の、名前空間を /demo にする指定と、マイナス2つの params-file で talker.yaml を渡す指定を付けて起動します。T2 では、ros2 topic list と、ros2 param get /demo/talker use_sim_time を実行します。

期待する結果は、T2 の分で、talker.yaml を渡した場合のものです。ros2 topic list の表示は抜粋で、トピック名が1行です。ros2 param get の表示は、真偽の値の1行です。

トピックが /demo/chatter になっていれば、名前空間が付いています。use_sim_time は False のままで、talker と書いた YAML の値が効いていません。demo_talker.yaml か all.yaml を渡した場合は、同じコマンドで、値が True になります。Python 版のデモ、つまり ros2 run demo_nodes_py talker でも、結果は同じです。
