# Tips集 3: ビルド中の SetuptoolsDeprecationWarning の意味（聞くための原稿）

これは、ros2MinimalPhysicalAi という教材の、Tips集の3つ目の項目です。

Tips集は、手順書、つまりフェーズの本文に入れると流れが途切れる、分量の少ない補足をまとめた資料です。どの項目も独立しているので、関係する手順書を読んでいるときや、疑問を持ったときに、その項目だけを読めばよい、とあります。

対象は、ROS2 Jazzy と Ubuntu 24.04 です。版に依存する記述は、この資料を作ったときに、/opt/ros/jazzy と Ubuntu のパッケージに入っていたもので確かめた、とあります。所要の目安は、1項目あたり5 から15分の読み物です。

この項目に関係する手順書は、フェーズ2 の2-4節です。

出どころについて、断りがあります。内容は、/opt/ros/jazzy のソースや、Ubuntu のパッケージの colcon-core と setuptools などを読んで確かめ、自分の言葉で書いたもので、ソースやドキュメントの転載ではない、とあります。3-1節の警告の文面は、使い捨ての環境で実際に表示させたもの、とあります。

この原稿では、警告の文面を書き写さずに、何が書かれているかを言葉で説明します。

## 3. ビルド中の SetuptoolsDeprecationWarning の意味

### 3-1. 警告の意味

フェーズ2 の2-4節では、Python のパッケージのビルド中に SetuptoolsDeprecationWarning が出ることがあり、ビルドが成功していれば無視してよい、とだけ書きました。この警告の意味は、次のとおりです。

まず、名前の2つの部分です。

setuptools は、Python のパッケージをビルドしたり、インストールしたりするための道具です。ament_python のパッケージにある setup.py は、setuptools の書き方です。

DeprecationWarning は、非推奨の警告です。今は動くが、将来の版で使えなくなる予定の使い方をしている、という予告です。エラーではないので、ビルドはそのまま続きます。

何が非推奨なのかというと、setup.py を直接実行してインストールする使い方です。Python のパッケージの作り方は、pyproject.toml という設定ファイルと、pip などの、標準化された道具を使う方式へ移ってきています。一方、colcon は、ament_python のパッケージをビルドするとき、裏で python3 setup.py を直接実行しています。マイナス2つの symlink-install を付けたときは setup.py develop、付けないときは setup.py install の形です。colcon のログの command.log に、実行したコマンドが残ります。setuptools から見ると、もう勧めていない使い方なので、警告を出します。

使い捨ての環境で、colcon を通さずに setup.py install を直接実行すると、警告が出ました。Ubuntu 24.04 の setuptools 68.1.2 で、前後の行は省略している、とあります。

期待する結果です。1行目は、SetuptoolsDeprecationWarning の名前に続いて、setup.py install が非推奨だという1文です。次に、感嘆符が2つだけの行があります。その後、星印を並べた横線の下に、英語の説明が数行続きます。

この説明は、setup.py を直接実行しないで、標準化された道具を使ってほしい、という内容です。setup.py develop のときは、同じ趣旨の EasyInstallDeprecationWarning も出ました。easy_install という、古いインストールの仕組みを使っている、という警告です。

### 3-2. 無視してよい理由と、ふだんは表示されない理由

この使い方を変えるのは、colcon と ROS2 の側の仕事で、パッケージを書く側が直せるものではありません。ROS2 Jazzy の組み合わせでは、この使い方で、ビルドが正しくできます。だから、ビルドが成功していれば、無視してよい、とあります。

実際には、colcon 自身が、この2つの警告を表示しないようにしています。colcon は python3 を、マイナス W の指定を2つ付けて実行しています。1つは、setup.py install が非推奨だという文言で始まる警告を無視する指定、もう1つは、easy_install のコマンドが非推奨だという文言で始まる警告を無視する指定です。マイナス W に、ignore、コロン、文言、の形で渡すのは、その文言で始まる警告を表示しない、という Python の指定です。Ubuntu 24.04 のパッケージ、つまり colcon-core 0.21.3 と setuptools 68.1.2 の組み合わせで、フェーズ2 の2つのパッケージを、colcon build マイナス2つの symlink-install でビルドしたところ、警告は1行も出なかった、とあります。

それでも警告を見かけることがあるのは、主に次の2つの場合です。

1つ目は、setuptools の版が違う場合です。pip で新しい setuptools を入れていると、警告の文言が変わり、colcon の指定に当たらなくなることがあります。colcon の指定は、文言の先頭が一致するかで判定するからです。ROS2 の Python のパッケージは、システムの Python、つまり apt で入れたものに合わせて作られているので、システムの側へ pip で setuptools を入れ直すことは避けます。

2つ目は、別の非推奨を踏んでいる場合です。例えば、setup.cfg に script-dir のような、ハイフンで区切った名前を書くと、アンダースコアで区切った script_dir を使ってほしい、という、別の SetuptoolsDeprecationWarning が出ます。setuptools 68.1.2 で実際に表示させて確かめた、とあり、文面の例は10-4節にあります。古い ROS2 の版に向けて書かれたパッケージや記事を、そのまま使うと出ることがあります。こちらは、パッケージを書く側で直せるので、警告の文面に出てくる名前に書き換えます。setup.cfg の役割と、警告の文面の例は、10節で扱います。

どちらの場合も、判断の基準は、フェーズ2 の4節の表と同じで、Summary の行で、失敗、つまり Failed が無いかを確かめます。警告の文面を読み、自分のパッケージのファイル名や項目名が出てくるなら直せる警告、そうでなければ道具の側の話、と見分けるとよい、とあります。
