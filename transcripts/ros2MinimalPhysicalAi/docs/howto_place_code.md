# サンプルコードを練習環境に置く方法（聞くための原稿）

これは、ros2MinimalPhysicalAi という教材の、手順書のサンプルコードを、自分の PC の練習環境に置く方法の資料です。

手順書のサンプルコードは、GitHub のページからコピーし、練習環境、つまりホームの ros2_ws のファイルに貼り付けて使います。そのまま貼り付けて使うことを想定しているので、コードを隅々まで暗記する必要はない、とあります。各行が何をしているかは手順書の解説を読んで理解し、書き方そのものは、必要になったときにサンプルを見返せばよい、とあります。

この資料では、その方法を2つ紹介します。どちらか一方を使えれば十分です。

方法A は、touch と nano を使う方法です。ターミナルだけで完結し、追加の導入は要りません。

方法B は、VS Code を使う方法です。Windows の側のエディタで、WSL の中のファイルを直接編集します。

対象は、フェーズ2 の2-7節、つまり雛形の hello.py と hello.cpp の文言を書き換えるところから後で、ファイルを作ったり書き換えたりするときです。サンプルコードを貼り付けるのは、フェーズ3-1 からです。所要の目安は10 から15分で、読み物と1回の練習を含みます。

期待する結果の出どころについて、断りがあります。方法A の touch、ls、head の表示は、使い捨ての環境で確かめたものと同じ形です。nano と VS Code の画面の様子は、それぞれの仕様から想定したもので、版によって細部が異なります。

この原稿では、表示を書き写さずに、何が表示されるかを言葉で説明します。

## 1. 手順書のどこを見ればよいか

手順書では、サンプルコードの直前に、置く場所が書いてあります。形は、ファイル、コロン、の後に、ros2_ws から始まるパスを続けたものです。原文の例は、ros2_ws の src の learn_py の learn_py の talker.py です。

この場合、ホームの ros2_ws の src の learn_py の learn_py に、talker.py というファイルを作り、その下のコードブロックの中身を丸ごと貼り付けます。

コードブロックにマウスを重ねると、右上にコピーのボタンが出ます。ボタンを使うと、コードブロックの中身だけを過不足なくコピーできます。手でドラッグして選ぶと、先頭や末尾の行が欠けやすい、とあります。

setup.py の entry_points や、CMakeLists.txt のように、既にあるファイルに数行を足す指示もあります。その場合は、ファイルを作り直さず、指示された位置に行を足します。これは4節で扱います。

以下では、フェーズ3-1 の talker.py を例にします。フェーズ2 で learn_py パッケージを作ってあることが前提です。

## 2. 方法A: touch と nano で貼り付ける

### 2-1. ファイルを作る

コマンドは3つです。cd で、ホームの ros2_ws の src の learn_py の learn_py に移動します。touch talker.py で、ファイルを作ります。ls で、一覧を表示します。

期待する結果です。cd と touch は、成功しても何も表示しません。ls の一覧に、talker.py が加わります。一覧に並ぶのは、hello.py、__init__.py、talker.py の3つです。並び順は、環境の言語の設定によって変わります。

touch は、中身が空のファイルを作るコマンドです。次の nano でもファイルは作られますが、先に touch で作って ls で確かめておくと、ファイル名の打ち間違いや、置く場所の間違いに早く気づけます。

cd で、No such file or directory と出る場合は、フォルダがまだありません。手順書に、フォルダを作る、とある場合は、mkdir マイナス p で作ってから cd します。

### 2-2. nano で開いて貼り付ける

コマンドは、nano talker.py です。

期待する結果です。ターミナルの画面が nano に切り替わります。1行目に、GNU nano 7.2 と、ファイル名が表示され、中身は空です。画面の下の2行に、^G で Help、^O で Write Out、^X で Exit などの、操作の一覧が出ます。^ の記号は、Ctrl キーのことです。

手順は4つです。

1つ目。GitHub のページで、コードブロックのコピーのボタンを押します。

2つ目。nano の画面で、Ctrl+Shift+V、またはマウスの右クリックで貼り付けます。Windows Terminal で長いコードを貼り付けると、貼り付けてよいかを確かめる画面が出ることがあります。その場合は、貼り付けを選びます。

3つ目。Ctrl+O を押します。画面の下に、File Name to Write、コロン、talker.py と出るので、Enter で保存します。Wrote 36 lines のように、書き込んだ行数が表示されます。行数は、コードによって変わります。

4つ目。Ctrl+X で nano を終わり、ターミナルに戻ります。

注意が3つあります。

保存せずに Ctrl+X を押すと、Save modified buffer、と聞かれます。Y を押すと保存で、その後にファイル名の確認で Enter を押します。N を押すと、保存せずに終わります。

貼り付け先の nano は、既定では、行頭の字下げを自動で足しません。これは Ubuntu 24.04 の nano の設定です。そのため、Python の字下げは、コピーしたとおりに入ります。

Ctrl+V は、nano では、次のページへ移動する操作です。貼り付けには、Ctrl+Shift+V を使います。

### 2-3. 中身を確かめる

コマンドは、head マイナス5 talker.py です。

期待する結果です。貼り付けたコードの、先頭の5行が表示されます。手順書のサンプルの先頭と同じなら、貼り付けは成功しています。talker.py の例では、import で始まる行が4つと、空の行が1つです。

何も表示されない場合は、保存していないか、つまり2-2節の手順の3つ目を飛ばしたか、別の名前で保存しています。ls でファイル名を確かめ、nano talker.py からやり直します。

表示が手順書と違う場合、例えば先頭の行が欠けている場合は、ファイルを消して作り直してもかまいません。rm talker.py の後、2-1節からやり直します。

## 3. 方法B: VS Code で開いて貼り付ける

VS Code は、Windows の側に入れたまま、WSL の中のファイルを直接開いて編集できます。そのために、VS Code の拡張機能の WSL を使います。Microsoft 製のものです。

### 3-1. 準備（最初の1回だけ）

1つ目。Windows の側に、VS Code を入れます。WSL の Ubuntu の中には入れません。

2つ目。VS Code の拡張機能の画面で WSL を探し、Microsoft が提供しているものを入れます。

### 3-2. ワークスペースを開く

Ubuntu のターミナルで、ワークスペースに移動してから、code ドット、を実行します。ドットは、今いるフォルダ、という意味です。コマンドは、cd でホームの ros2_ws に移動し、code ドット、の2つです。

期待する結果です。VS Code のウィンドウが開き、左のエクスプローラーに、ros2_ws の中身、例えば src などが並びます。ウィンドウの左下に、WSL、コロン、Ubuntu-24.04 のように表示されていれば、WSL の中のファイルを開いています。初めて実行したときは、WSL の中に、VS Code 用の部品の VS Code Server を入れるため、ターミナルに導入の進み具合が表示され、少し時間がかかります。

Windows のエクスプローラーから、WSL の中を指すパスをたどって開く方法もありますが、この教材では、code ドット、を使います。WSL の拡張機能を通さずに開くと、ファイルの読み書きが遅くなったり、ターミナルやビルドの結果とかみ合わなかったりすることがある、とあります。

code、コロン、command not found と出る場合は、Windows の側の VS Code を入れた後に、WSL のターミナルを開き直します。

### 3-3. ファイルを作って貼り付ける

手順は4つです。

1つ目。左のエクスプローラーで、src、learn_py、learn_py の順に開きます。

2つ目。内側の learn_py のフォルダを右クリックし、新しいファイル、を選んで、talker.py と入力して Enter を押します。

3つ目。開いた空のファイルに、GitHub のページでコピーしたコードを、Ctrl+V で貼り付けます。

4つ目。Ctrl+S で保存します。

期待する結果です。エクスプローラーの learn_py の learn_py の下に、talker.py が並びます。保存の前は、タブのファイル名の横に黒い丸が付き、保存すると消えます。ターミナルで、2-3節と同じ head マイナス5 talker.py を実行すると、貼り付けたコードの先頭が表示されます。

補足が2つあります。

VS Code のウィンドウの中でも、日本語のキーボードの場合は、Ctrl とアットマークのキーで、ターミナルを開けます。このターミナルは WSL の Ubuntu のもので、colcon build などをそのまま実行できます。

VS Code の WSL の環境では、改行のコードは Linux の形、つまり LF で保存されます。Windows の形の CRLF になっていると、スクリプトの実行でエラーになることがあります。右下のステータスバーに LF と出ていれば、問題ありません。

## 4. 既にあるファイルに行を足す場合

setup.py の entry_points に1行を足す、CMakeLists.txt の ament_package の前に数行を足す、といった指示の場合は、ファイルを開いて、指示された位置にカーソルを動かしてから貼り付けます。

nano の場合は、nano setup.py で開き、矢印のキーでカーソルを動かして、貼り付けます。行を探すときは、Ctrl+W で文字を検索できます。例えば、entry_points と入力して Enter を押します。保存と終了は2-2節と同じで、Ctrl+O、Enter、Ctrl+X の順です。

VS Code の場合は、エクスプローラーからファイルを開き、指示された位置をクリックして貼り付け、Ctrl+S で保存します。Ctrl+F で文字を検索できます。

フェーズ2 の2-7節のように、既にある行の文言を書き換える場合も、開き方と保存のしかたは同じです。nano hello.py で開き、書き換える文字の位置へカーソルを動かして直します。

足す位置を間違えると、ビルドや実行でエラーになります。手順書に書かれた、どの行の後、または前に足すかを確かめ、足した後に cat で、前後の行と一緒に見直すとよい、とあります。
