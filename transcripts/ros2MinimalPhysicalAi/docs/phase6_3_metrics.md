# フェーズ6-3: 記録から指標を計算して比べる（聞くための原稿）

これは、ros2MinimalPhysicalAi という教材の、フェーズ6-3 の手順書の話です。学習計画のフェーズ6 の6-3、元のアイデアのステップ4 に当たります。フェーズ6-1 で取った記録を再生しながら、解析のノードで、追従の指標を計算し、条件ごとに比べます。指標は、行き過ぎ量、立ち上がり時間、整定時間、定常偏差、ペダルが張り付いた時間、追従誤差の二乗平均の6つです。グラフで見た違いを、数で言えるようにするのが、この手順書の目的です。

想定する環境は、WSL2 と Ubuntu 24.04 と ROS2 Jazzy です。前提はフェーズ6-1 で、4-5節の sim_default、5節の gz_default、4-6節の slow_brake の、3つの記録があることです。所要時間の目安は1から2コマで、言語は Python です。

進め方の囲みです。2節で指標の定義を決め、3節で時間の数え方を考えます。4節で、指標を ROS2 を使わない関数として書き、フェーズ5-2 の閉ループの計算に当てはめて確かめます。5節で解析のノードを書き、6節で記録を解析し、7節で3つの条件を比べ、8節で強化学習とのつながりを考えます。サンプルは、学習の手がかりとして最小限に書いたもので、公式チュートリアルの転載ではありません。コードは、手順書を作るときに、使い捨ての環境でビルドし、フェーズ6-1 と同じ方法で取った記録を、実際に解析して確かめました。出力が違う場合は、実機の表示を優先します。

期待する結果の出どころの囲みもあります。4節の計算の結果、6節と7節の解析のノードのログと、ros2 topic info と ros2 bag play の表示は、使い捨ての環境で実際に実行した表示で、時刻は実行ごとに違います。手順書を作るときには、再生を進めるのに、スペースキーの代わりに、同じ処理を呼ぶ ros2 bag play のサービス /rosbag2_player/resume を使いました。サービスは、要求を送ると1回だけ応答が返る通信の形で、任意のフェーズ3-4 で扱います。ここでは、ros2 bag play が、再生の一時停止と再開をコマンドから操作できるように用意しているものを使いました。指標の値は、同じ記録なら同じになりますが、記録を取り直すと少し変わります。5-3節のビルドの表示も、使い捨ての環境でビルドしたときの表示で、成功を見分ける行だけの抜粋です。

この原稿では、数式は記号の意味を添えて言葉で読み、サンプルコードは書き写さずに、ブロックの構成と要の行を言葉で説明します。ツールの表示も、何が表示されるかを言葉で説明します。同じ指標の値が何度も出てくるので、値は、なるべく1回だけ読みます。

## 0. 学習目標と完了の条件

学習目標は3つです。

1つ目。6つの指標の定義を説明し、ROS2 を使わない関数で計算できる。

2つ目。記録を再生しながら、解析のノードで指標を計算し、条件ごとの比較表を作れる。

3つ目。指標の時間を、記録の時刻ではなく、受け取った速度の数かけるプラントの周期、で数える理由を説明できる。

完了の条件です。3つの記録の比較表を作ります。3つとは、フェーズ5-3 の既定、フェーズ5-3 で tau_brake を1.0 にしたもの、フェーズ5-4 の既定です。そして、制御の効き方の違い、つまり立ち上がり、行き過ぎ、定常偏差の違いと、アクセルとブレーキの非対称性を、表の数で説明できることです。

## 1. 全体像

フェーズ6-1 の6節では、フェーズ5-3 と5-4 の記録を重ねて、2つのことを目で確かめました。フェーズ5-4 は、目標の毎秒10メートルを少し行き過ぎること。目標を毎秒5メートルに下げた直後、フェーズ5-4 だけが5 を少し下回ることです。では、フェーズ5-4 の行き過ぎは何パーセントでしょうか。フェーズ5-3 より速く目標に届いているのか、遅いのか。グラフを見ながら予想してから、この手順書で数を出して、答え合わせをします。

2つ目。指標の計算は、フェーズ5-1 や5-2 と同じく、ROS2 を使わない関数、metrics.py に分けます。こうすると、フェーズ5-2 の closed_loop_sim.py の計算結果にも同じ関数を当てはめられ、記録を解析した値と、答え合わせができます。

## 2. 指標の定義

### 2-1. 段ごとに見る

目標速度は、0 から10、5、0 と、階段状に変わります。単位は毎秒メートルです。目標が変わってから、次に変わるまでを、段と呼び、指標は段ごとに計算します。加速の段の0 から10 と、減速の段の10 から5 と5 から0 を分けて見ると、アクセルとブレーキの非対称性が、数に表れます。フェーズ5-3 の4-3節で見た非対称性です。ただし、追従誤差の二乗平均の RMS だけは、記録全体で1つの数にします。2-2節で扱います。

### 2-2. 6つの指標

段の変わる前の目標を r ゼロ、変わった後の目標を r イチ とし、変化の大きさを、r イチ から r ゼロ を引いた差の絶対値とします。原文では、この変化の大きさを、デルタの絶対値、と書いています。

表は3列で、6行あります。列は、指標、表の列の名前、定義です。

1行目は、行き過ぎ量で、表の列は over、単位はパーセントです。変わった向きに、速度が r イチ をどれだけ超えたか、です。超えた量の最大値を、変化の大きさで割って、100 を掛けます。

2行目は、立ち上がり時間で、表の列は rise、単位は秒です。速度が、変化の10パーセントに届いてから、90パーセントに届くまでの時間です。

3行目は、整定時間で、表の列は settle、単位は秒です。段の始まりから、速度が、r イチ のプラスマイナス、変化の大きさの0.02倍、という帯に入って、その後ずっと出なくなるまでの時間です。段の終わりまでに収まらなければ、ハイフンを出します。

4行目は、定常偏差で、表の列は error です。r イチ から、段の最後の1秒の速度の平均を引いたものです。

5行目は、張り付いた時間で、表の列は sat、単位は秒です。ペダルが、プラス1 かマイナス1 に張り付いていた時間の合計です。

6行目は、追従誤差の二乗平均で、表の列は RMS error です。最初に目標が変わってから最後までの、目標から速度を引いたものの2乗の、平均の平方根です。RMS は、Root Mean Square、二乗平均平方根の略です。

この手順書で詳しく扱うのは、行き過ぎ量、整定時間、RMS の3つです。

行き過ぎ量は、目標をどれだけ超えたか、です。車両では、超えた分だけ乗り心地が悪く、前の車に近づきすぎます。0パーセントが理想ですが、0パーセントを目指すと、目標へ近づくのが遅くなりやすいです。

整定時間は、目標のまわりに落ち着くまでの時間です。行き過ぎて戻ってくる場合も、ゆっくり近づく場合も、この時間は長くなります。どれだけ早く、次の目標に移れる状態になったかを、1つの数で表します。

RMS は、記録全体の追従の良し悪しを、1つの数で表します。大きく外れた時間が長いほど大きくなり、2乗するので、大きな外れほど強く効きます。目標が変わった直後は、どんな制御でも大きく外れるので、RMS は、目標の変わり方にも左右されます。同じ目標の階段で比べるときに使います。

残りの3つも、7節の比較表を読むのに使います。

立ち上がり時間は、目標が変わってから、目標の近くまで速度が動く速さです。長いと、目標を変えても、なかなか追いつきません。前の車が加速したのに、ついていけない、という状態です。

定常偏差は、最後に目標とずれたまま残る量です。フェーズ5-2 の2-2節の、P 制御だけのときの偏差です。残ると、いつまでたっても、目標の速さで走れません。

張り付いた時間は、アクセルやブレーキを踏み切っていた長さです。フェーズ5-2 の2-5節のワインドアップの話です。長いほど、制御器の計算よりも、車両の力の限界で動きが決まっていた時間が長い、ということです。

指標の基準の取り方について、補足の囲みがあります。3つの点です。

1つ目は、一般的な定義です。制御工学では、行き過ぎ量や整定時間の帯を、最終値、ここでは r イチ に対する割合で決めることが多いです。帯の幅は、プラスマイナス2パーセントのほかに、5パーセントもよく使われます。立ち上がり時間は、10パーセントから90パーセントのほかに、0パーセントから100パーセントで測ることもあります。

2つ目は、このサンプルで、変化の大きさを基準にした理由です。この手順書の階段には、最終値が0 の段、つまり5 から0 の段があります。最終値に対する割合で決めると、帯の幅が0 になり、計算できません。そこで、どの段でも同じ式で計算できるように、変化の大きさを基準にしました。

3つ目は、実務の目安です。どの定義を使うかは、比べる相手、たとえば仕様書や、ほかのチームの結果に合わせます。定義が違うと、同じ動きでも数が変わります。比較表には、どの定義で計算したかを、必ず添えます。

## 3. 時間の数え方

立ち上がり時間や整定時間を計算するには、各サンプルの時刻が要ります。ところが、記録の時刻をそのまま使うと、次の3つの理由で、プラントの中で過ぎた時間とずれます。

1つ目は、PC の時計の飛びです。記録の時刻は PC の現在時刻で、時計が飛ぶと、その分だけ間があきます。フェーズ6-1 の2-2節の注記の話です。

2つ目は、再生の速さです。この手順書では、5倍の速さ、つまり -r 5 で再生します。届いた時刻で測ると、時間が5分の1に縮みます。任意のフェーズ6-2 の7節の末尾の課題2 で、2倍の速さで再生すると、案A の距離が約半分になったのと同じです。

3つ目は、シミュレーションの遅れです。フェーズ5-4 の一式は、Gazebo の計算が現実より遅れることがあります。フェーズ6-1 の5節の注記の話です。

そこで、解析のノードは、受け取った速度の数に、プラントの周期を掛けて、時刻を数えます。

フェーズ5-3 の vehicle_plant は、モデルを0.01秒ずつ進めるたびに、速度を1回送ります。フェーズ5-1 の5-1節の on_timer です。速度の n 番目は、プラントの中で、ちょうど n かける0.01秒の時点の値です。

フェーズ5-4 の gz_plant は、Gazebo のオドメトリが届くたびに、速度を送ります。フェーズ5-4 の4-3節の on_odom です。オドメトリは、シミュレーション時刻で、1秒に50回、つまり0.02秒ごとに送られます。フェーズ5-4 の2-2節の odom_publish_frequency の設定です。

こうすると、時刻は、プラント自身が進めた時間になり、PC の時計の飛び、再生の速さ、シミュレーションの遅れの、どれにも左右されません。その代わり、途中の速度が1つでも届かないと、それ以降の時刻がずれます。6節で、受け取った数を、記録の数と比べて確かめます。

## 4. 指標の計算を ROS2 なしで確かめる、metrics.py

ファイルは、ros2_ws の src の learn_py の learn_py の metrics.py です。

90行ほどのコードで、ブロックは6つと、最後に main を呼ぶ2行です。6つのブロックは、dataclass の import、1つの段の指標をまとめるデータクラス StepResult、関数の evaluate、evaluate_step、format_report、そして main です。

StepResult のフィールドは7つで、変わる前の目標、変わった後の目標、行き過ぎ量、立ち上がり時間、整定時間、定常偏差、張り付いた時間です。evaluate の引数の帯の幅 band の既定は0.02、最後の区間の長さ final_window の既定は1.0秒で、2-2節の表の定義に当たります。evaluate_step は、行き過ぎ、立ち上がり、整定、定常偏差、張り付き、の順に、コメントを付けて計算します。format_report は、表の見出しの行、段ごとの行、RMS の行を、文字列のリストにします。

要の行は1か所で、evaluate_step の、張り付いた時間を求める行です。ペダルの絶対値が、1 から10 のマイナス9乗を引いた値以上のサンプルについて、次のサンプルまでの時間を足し合わせます。比べる相手は、ちょうど1 ではなく、1 よりごくわずかに小さい値です。

metrics.py の解説は、5つです。

1つ目は StepResult です。1つの段の指標をまとめるデータクラスで、フェーズ5-1 の VehicleParams と同じ、dataclass の書き方です。値が無いことがある2つ、つまり立ち上がり時間と整定時間は、None にします。

2つ目は evaluate です。時刻、目標、速度、ペダルの4つの並びを、同じ長さで受け取ります。目標が、前のサンプルと変わったところ、つまり changes で段に分け、段ごとに evaluate_step を呼びます。RMS は、最初に目標が変わったところから、最後までの誤差で計算します。最初の目標0 の区間は、止まっていて誤差が0 なので、入れると RMS が小さく出てしまうためです。

3つ目は evaluate_step で、2-2節の表の定義を、そのままコードにしたものです。sign は変化の向きで、上げたらプラス1、下げたらマイナス1 です。x から r1 を引いて sign を掛けると、上げたときも下げたときも、変わった向きに超えた量を、同じ式で求められます。立ち上がりで使う next は、条件に合う最初の時刻を返し、無ければ None を返す Python の書き方です。整定時間は、帯の外にいたサンプルの番号を集め、最後の外のサンプルの、次の時刻を使います。最後のサンプルまで外にいれば、収まらなかったとして None にします。

4つ目は format_report です。表の行を、文字列のリストにします。値が None の欄は、ハイフンを表示します。5節のノードも、同じ関数でログを作ります。

5つ目は main です。フェーズ5-2 の4-2節の simulate の結果に、指標を当てはめます。説明は3つあります。

まず、simulate は、時刻、目標、速度、ペダルの組を、時刻の順に並べたリストを返します。フェーズ5-2 の4-2節の rows.append の部分です。0秒から目標10 で始まるので、その前に、目標0 の組を1つ足して、0 から10 の段を作っています。足す組は、0.01秒前、目標0、止まっている、ペダル0 です。

## 8. 強化学習へのつながり

1つ目は報酬です。全体の1つの数、つまり誤差の2乗の平均、これは RMS の2乗に当たりますが、これに、行き過ぎを重み20 で減点する項を足して、符号を反転しました。段ごとの行き過ぎ量のパーセントをそのまま足す代わりに、目標を越えた速度の差を2乗したものを、時間について積み上げる形にし、学習しやすいように、全体を10倍しました。重みを変えると、追従の速さと行き過ぎのバランスが変わることも、フェーズ7、つまり任意のフェーズ7-2 と、フェーズ7-4 で確かめます。

2つ目は、環境の形です。フェーズ7-1 の環境と、フェーズ7-3 と7-4 の Gazebo の環境は、同じ観測、行動、報酬、始め方にしました。フェーズ7-3 の4節の話です。どちらも、止まった車両から始めて、0.1秒ごとにペダルを選びます。

3つ目は、エピソードの終わり方です。フェーズ6-1 と同じく、時間で終わる形、90秒にしました。目標速度は、フェーズ6-1 の決まった階段ではなく、10秒ごとにランダムな幅で上下するシナリオにしました。

4つ目は、指標の関数です。このページの metrics.py の evaluate を、フェーズ7-1 と7-4、任意のフェーズ7-2 でも、学習の結果を人が読める数で確かめるのに、そのまま使いました。フェーズ7-5 では、このページの metrics ノードで、PI 制御と NN の記録を比べました。

## 9. 本フェーズのまとめ

4つあります。

1つ目。指標は、段ごと、つまり行き過ぎ量、立ち上がり時間、整定時間、定常偏差、張り付いた時間と、記録全体、つまり RMS で計算しました。段ごとに見ると、アクセルとブレーキの非対称性や、ブレーキの遅れが減速の段にだけ効くことが、数で分かります。

2つ目。指標の計算は、ROS2 を使わない関数に分けたので、フェーズ5-2 の閉ループの計算にも、記録の解析にも、同じ関数を使えました。

3つ目。時間は、記録の時刻ではなく、受け取った速度の数かけるプラントの周期、で数えました。PC の時計の飛び、再生の速さ、シミュレーションの遅れに左右されない代わりに、途中の欠けに弱いので、受け取った数を、記録の数と比べて確かめます。

4つ目。再生は一時停止の状態で始め、解析のノードがつながってから進めます。そうしないと、つながる前の分が届きません。

## 10. つまずきやすい点

表は2列で、6行あります。列は、症状と、確認することです。

1行目。表に0 から10 の段が無い、または立ち上がり時間が短すぎる場合です。再生を始める前に、解析のノードがつながっていたかを確かめます。-p で始め、Subscription count を確かめてから、スペースキーを押します。この手順書の6-1節の話です。

2行目。サンプルの数が、記録より大きく少ない場合です。再生を始めた後に、解析のノードを起動していないかを確かめます。数が合わないと、3節のとおり、時刻がずれます。

3行目。フェーズ5-4 の記録の時間が、2倍や半分に出る場合です。sample_period を0.02 にしたかを確かめます。7-1節の話です。

4行目。metrics が、表を出さずに止まらない場合です。再生が終わってから、idle_timeout の2秒を待ちます。一時停止のままなら、T1 でスペースキーを押したかを確かめます。

5行目。python3 -m learn_py.metrics で、No module named learn_py、つまり learn_py というモジュールが無い、と出る場合です。ビルドして、source install/setup.bash をしたかを確かめます。フェーズ5-2 の9節の表と同じです。

6行目。表の数が途中で切れている、または段が足りない場合です。再生の途中で、スペースキーをもう一度押して、一時停止していないかを確かめます。一時停止のまま、idle_timeout の2秒がたつと、それまでの分だけで計算して終わります。記録を再生し直して、解析もやり直します。

## 11. フェーズ6 のまとめ

フェーズ6-1 から6-3 で作ったものの表があります。表は3列で、3行あります。列は、ページ、作ったもの、役割です。

1行目は6-1 です。作ったものは、target_generator の end_time、on_exit=Shutdown()、record.launch.py、そして名前が _record.yaml で終わる YAML です。役割は、フェーズ5-3 と5-4 の一式を記録し、決めた時間で終わらせること、そして記録を再生して重ねることです。

2行目は、任意の6-2 です。作ったものは、goal_monitor、record_goal.launch.py、名前が _goal.yaml で終わる YAML です。役割は、ゴールに着いたことをきっかけに、記録を終わらせることです。

3行目は6-3 です。作ったものは、metrics.py と metrics です。役割は、記録から指標を計算して、条件ごとに比べることです。

学習計画のフェーズ6 の完了の条件、つまり、記録から条件ごとの指標の比較表を作り、制御の効き方の違いを説明する、という条件は、この手順書の7-2節で確かめました。
