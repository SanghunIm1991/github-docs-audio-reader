完了の条件です。4節で、Walker2d を10万ステップ学習させ、または期待する結果を読み、まだ歩けていない理由を、収益の内訳と学習の量から説明できること。6節を読み、次に何を学べばよいかを、自分の言葉で書けることです。

## 1. 全体像

このプロジェクトのアイデアは、最初から二足歩行のロボットを見据えていました。ただ、二足歩行は、計算の負荷も、要る知識も大きいです。そこで、まず慣性のある車両の速度の追従を題材にして、ROS2、物理シミュレータ、記録と評価、強化学習を、一通り学んできました。

二足歩行では、何が変わるのか。いちばん大きいのは、何もしないと倒れることです。車両は、ペダルを離せば、やがて止まって落ち着きます。二足のロボットは、関節に力を入れ続けないと、すぐに倒れます。しかも、関節は1つではなく、全身の関節の力を、同時に、細かく合わせる必要があります。人が PI 制御のような簡単な式を書くのが難しいので、強化学習がよく使われる分野の1つです。フェーズ7-0 の6-2節の、強化学習が力を発揮するのは、式を立てにくい問題、つまり接触や摩擦が複雑で、観測が多い問題だ、という話です。

このページでは、まず、二足を小さく試します。Gymnasium にある、MuJoCo の環境 Walker2d は、2次元、つまり前後と上下だけで動く、脚が2本の簡単なロボットです。MuJoCo は、物理シミュレータの1つです。これを、フェーズ7-0 から7-4 と同じ SB3 の SAC で学習させ、車両と、どれだけ勝手が違うかを体験します。そのうえで、本格的に二足歩行を学習させるときに使われる道具と、要る PC の性能を読みます。

ここに図が1枚あります。SVG と mermaid の版がありますが、内容は同じです。

図には、横長の箱が4つ、左から右へ並び、隣どうしが右向きの実線の矢印でつながっています。1つ目は薄い青の箱で、車両、7-3 から7-5、観測5、行動1、PI 制御と NN を比べる、Gazebo と ROS2 のノード、と書いてあります。2つ目は薄いオレンジ色の箱で、二足を試す、7-6、Walker2d、MuJoCo、観測17、行動6、作成に使った PC の CPU で、と書いてあります。3つ目は灰色の点線の箱で、大量に学習、Isaac Lab と MuJoCo Playground、rsl_rl と skrl、数千の環境を並べる、GPU、と書いてあります。4つ目は薄い緑の点線の箱で、ROS2 でロボットへ、URDF と tf2、ros2_control、Gazebo と実機、と書いてあります。図の下には、点線の2つは、このページでは読み物として扱う、という注があります。

まとめると、フェーズ7-3 から7-5 の車両の題材から、このページで二足を小さく試し、性能の高い PC の GPU で数千の環境を並べて大量に学習し、ROS2 でロボットへつなぐ、という流れの図です。

## 2. MuJoCo を入れる

MuJoCo は、Google DeepMind が公開している物理シミュレータで、ロボットの学習の研究でよく使われます。ライセンスは Apache License 2.0 です。CPU で動き、Python から pip で入れられます。Gymnasium の二足の環境を使うには、Gymnasium の追加の部品、つまり mujoco の追加の指定として、MuJoCo の Python のパッケージと、関係するパッケージを入れます。

強化学習の仮想環境、つまり強化学習の環境構築のページの、ホームの rl_venv を有効にしたターミナルで実行します。Gymnasium の版は、環境構築の4節で入れた1.3.0 にそろえます。source で、ホームの rl_venv の bin の activate を読み込み、pip install で、gymnasium に mujoco の追加の指定を付け、版を1.3.0 にしたものを入れます。

期待する結果です。原文には、末尾の1行だけが載っています。Successfully installed に続いて、新しく入れたパッケージの名前と版が並びます。

読み方です。並びの中に、mujoco の3.15.0 があれば成功です。Gymnasium 本体や numpy は、すでに入っているので、すでに条件を満たしている、という意味の Requirement already satisfied と表示され、入れ直されません。並んだ版は作成時のもので、mujoco などは、入れた時期によって新しい版になることがあります。Gymnasium 1.3.0 の mujoco の追加の指定は、mujoco の2.1.5 以上を求めます。並びの中の glfw と pyopengl は、4-4節の任意の、動きを見る、で、ウィンドウに描くための部品です。

## 3. 二足の環境を確かめる

3つ目は、でたらめな行動です。env.action_space.sample() で、行動の範囲から、でたらめに選びます。フェーズ7-0 の3-1節と同じです。env.action_space.seed に種を渡して、でたらめの選び方も種で決め、何度実行しても同じ結果になるようにします。倒れるとエピソードが終わる、つまり terminated になるので、終わるまでの長さと、そのときの時間を表示します。

### 3-2. 動かす

cd でホームの rl_practice に移り、python で check_walker.py を実行します。

期待する結果です。最初に、観測の空間、行動の空間、1ステップの秒数 dt の3行が出ます。続いて、見出しの行のあと、種0 から4 の5行が並びます。各行は、種、収益、長さ、時間です。

読み方は4つです。

1つ目は、観測は17個、ということです。Gymnasium の公式の文書によると、胴体の高さと角度、両脚の6つの関節の角度で、ここまでで位置が8つです。それと、胴体の速度と角速度と、6つの関節の角速度で、速度が9つです。10節の資料の話です。前後の位置そのものは、観測に入りません。

2つ目は、行動は6個、ということです。両脚の、ももの付け根、ひざ、足首の関節にかけるトルクで、マイナス1 から1 です。車両のペダルは1つでした。

3つ目は、1ステップは0.008秒、ということです。MuJoCo の物理を、0.002秒ずつ4回進めます。車両の環境の0.1秒ごとより、ずっと細かいです。1エピソードは、最長1000ステップ、つまり8秒で、それより前に倒れると終わります。

4つ目は、でたらめな行動では、0.1 から0.4秒で倒れる、ということです。14 から46ステップで終わり、収益も、ほぼ0 です。車両なら、ペダルをでたらめに踏んでも、90秒走り続けました。エピソードは、時間で終わりました。二足では、倒れることが、そのままエピソードの終わりになります。

報酬は、Gymnasium の公式の文書によると、1ステップごとに、次の3つを足したものです。

1つ目は、立っている分です。倒れていなければ1 です。胴体の高さが0.8 から2.0メートル、角度がマイナス1 から1ラジアンの範囲にあることが、倒れていない条件で、範囲を外れると、エピソードが終わります。

2つ目は、前に進んだ分です。そのステップの前向きの速さ、つまり進んだ距離を0.008秒で割ったものです。

3つ目は、力の罰です。トルクの大きさの2乗の和に、0.001 を掛けたものを引きます。

車両の報酬、つまりフェーズ7-1 の2-5節の報酬は、目標との差と行き過ぎ、つまり目標への追従のよさだけを見ていました。二足の報酬は、倒れない、前に進む、力を使いすぎない、の3つを、同時に求めます。

要の行は1か所で、main の繰り返しの中の、途中経過を表示する行です。行の最後で flush を True にして、表示をためずに、すぐに画面に出します。

train_walker.py の解説は、4つです。

4つ目は、保存です。最後に、walker_sac_100000.zip のような名前で保存します。4-4節の任意の、動きを見る、で使います。

## 5. 車両の題材との違い

車両と二足を比べた表があります。表は3列で、8行あります。列は、比べる項目、フェーズ7-3 から7-5 の車両、Walker2d の二足です。

### 6-1. 足りない知識

車両の題材で学んだこと、つまり ROS2 のノード、トピック、launch、物理シミュレータ、記録と指標、強化学習の環境、報酬、学習、評価は、二足歩行でも、そのまま土台になります。そのうえで、次の5つのことが加わります。

1つ目は、接触です。足が地面に着く、離れる、滑る。接触の瞬間に力が急に変わるので、車両の車輪の転がりより、シミュレーションも制御も難しいです。

2つ目は、バランスです。重心の位置と、足の裏が地面に着いている範囲の関係で、倒れるかどうかが決まります。歩行では、片足で立つ間も、倒れないように重心を運びます。

3つ目は、歩き方の型です。脚をどの順番で、どのくらいの周期で動かすか、です。強化学習では、報酬や観測に、この型の手がかりを入れることが多いです。

4つ目は、状態の推定です。シミュレーションでは、胴体の高さや速度を、直接読めます。このページの観測のとおりです。実物のロボットでは、関節の角度のセンサや、加速度と角速度を測るセンサ、つまり IMU から、推し量る必要があります。

5つ目は、シミュレーションと実物の違いです。フェーズ7-3 の1節で見たとおり、式やシミュレータで学んだものは、違う物理の上では、そのまま通用するとは限りません。二足歩行では、学習中に、摩擦や質量、センサの雑音などを、わざとランダムに変え、どれにも耐える方策を学ばせる方法、つまりドメインランダム化が、よく使われます。

### 6-2. 学習の量と、GPU で環境を並べること

4-2節の学習は、1つの環境を1ステップずつ進め、作成に使った PC、つまり専用の GPU が無い PC の CPU で、1秒あたり約84ステップでした。10万ステップで、約20分です。

二足やヒューマノイドのロボットの学習では、桁違いの量の経験を使います。Isaac Lab の公式の文書には、強化学習のライブラリの速さを比べた例があります。10節の資料の話です。1台の GPU、つまり NVIDIA GeForce RTX 4090 で、ヒューマノイドの環境、つまり Isaac-Humanoid-v0 を4096個並べ、合わせて約6550万ステップを、約200秒で学習させています。ライブラリによって、198 から287秒です。同じ量を、4-2節の速さで1つずつ計算すると、6550万を84 で割って、約78万秒、つまり約9日かかります。

この差を生むのは、物理の計算を、GPU で、何千もの環境について同時に行うことです。フェーズ7-4 の3-1節では、Gazebo の環境は、1つのワールドに1つしか作れず、1ステップずつ進めました。GPU で動く物理シミュレータ、つまり Isaac Lab や MuJoCo Playground は、何千ものロボットを同時に進め、その経験をまとめて、NN の学習に使います。強化学習のライブラリも、この並べ方に合わせて作られたものが使われます。6-3節の話です。

### 6-4. ROS2 の側で要るもの

学習した方策を、ROS2 でロボット、つまりシミュレータか実物につなぐには、フェーズ7-5 と同じ考え方、つまり重みを読むノードを、制御器の代わりに置くことに加えて、次の3つの部品が要ります。どれも、このプロジェクトでは、まだ扱っていません。

1つ目は、URDF です。ロボットの形、つまりリンクと関節、質量、見た目を書くファイルの形式です。脚の長さや関節の範囲を、ROS2 とシミュレータで共有します。

2つ目は、tf2 です。ロボットの各部分、つまり胴体、脚、足の、位置と向きの関係を、時刻つきで管理する仕組みです。関節の角度から、足先がどこにあるかを求めるのに使います。

3つ目は、ros2_control です。関節のモータに指令を送り、状態を読む部分を、決まった形で書くための枠組みです。シミュレータと実物で、同じ制御のノードを使い回しやすくなります。

アイデアの元のステップ7 では、これらを、車両の簡単な URDF から練習することを、候補に挙げています。
