# フェーズ7-2: 強化学習でゲインを調整する、任意（聞くための原稿）

想定する環境は、WSL2 と Ubuntu 24.04 と ROS2 Jazzy です。学習は ROS2 を使わず、ワークスペースのコードだけを借ります。前提は、フェーズ7-1 です。ホームの rl_practice に vehicle_env.py があり、フェーズ7-1 の3節の準備で、learn_py を読み込めることです。所要時間の目安は3から4コマで、計算を待つ時間が、課題を除いて17分程度あります。言語は Python で、ROS2 のノードは書きません。

## 0. 学習目標と完了の条件

学習目標は8つです。

1つ目。フェーズ7-1 のペダルを選ぶ環境と、このページのゲインを選ぶ環境の違い、つまり選ぶもの、選ぶ間隔、観測、始め方を説明できる。

2つ目。マイナス1 から1 の行動を、ゲインに引き延ばす方法と、最初の目標の速度で落ち着いた状態から始める方法を説明し、ゲインを選ぶ環境を書ける。

3つ目。ゲインと収益の表から、プラントによって、最もよいゲインが変わることを説明できる。

4つ目。学習させる前に、手で決めたゲインと、格子の探索の最良を比べて、改善の余地を確かめられる。

5つ目。エピソードの始めにゲインを1組選ぶ形で、SAC にゲインを学習させられる。

6つ目。学習が進まないときに、NN の更新の回数、つまり gradient_steps を見直し、エントロピーの係数の変化と合わせて、その理由を説明できる。

7つ目。行き過ぎの重みを変えると、最もよいゲインと、追従の様子が変わることを、格子の探索とフェーズ6-3 の指標で説明できる。これは、追従の速さと行き過ぎのトレードオフ、つまり一方をよくすると他方が悪くなる関係です。あわせて、収益の地形が平らに近いと、学習がよい組を見つけにくいことを説明できる。

8つ目。強化学習と格子の探索を比べ、選ぶ数が2つだけの問題では、格子の探索で十分なことと、強化学習が向く場面を説明できる。

完了の条件です。2節で、環境を点検し、ゲインと収益の表から、既定のプラントでは、既定のゲインが最もよい組に近いのに対し、ブレーキの遅いプラントでは、最もよいゲインが大きく変わることを説明できること。3節で改善の余地を確かめ、4節の丸1 と丸2 の途中経過の違いを説明できること。そのうえで、5節の比較表から、重みを変えると、最もよいゲインと、行き過ぎ量や RMS がどう変わるかを、格子の最良どうしで説明できることです。

## 1. 全体像

フェーズ7-1 では、方策がペダルを直接選ぶ環境を作りました。最終ゴールまでの道筋、つまりフェーズ7-3 から7-5 は、その形で、PI 制御の式そのものを NN に置き換えます。このページでは、寄り道として、もう1つの形を試します。PI 制御の式は残し、そのゲインだけを強化学習で選ばせる形です。

フェーズ5-2 では、PI 制御のゲインを、式から目安を立て、シミュレーションで確かめながら、手で決めました。フェーズ5-2 の6-5節では、ブレーキの時定数を変えると、同じゲインでも減速で行き過ぎることを見ました。プラントが変わって、手で決めたゲインが合わなくなったとき、人がゲインを調整し直すのは手間がかかります。この調整を、強化学習のエージェントに任せられないか。これが、このページの題材です。題材にするのは、フェーズ7-1 と同じく、ブレーキの時定数を1.0秒にした、ブレーキの遅いプラントの1つです。時定数が変わるたびに選び直す形を扱わない理由は、このページの2-7節の話です。

ただし、学習させる前に、確かめておくことがあります。手で決めたゲインが、すでに最もよい組とほとんど同じなら、どんなに学習がうまくいっても、得られるものは小さいです。そこで、まず強化学習を使わずに、ゲインを格子状に全部試して、手で決めたゲインと、最もよい組の差を測ります。2-7節で粗く、3-2節で細かく測ります。そのうえで学習させ、学習したゲインを、収益とフェーズ6-3 の指標で、手で決めたゲインや格子の最良と比べます。

学習させるのは、走り始めにゲインを1組だけ選び、走り切るまで変えない形です。これは、フェーズ5-2 で人が行った調整、つまりゲインを決めて、走らせて、結果を見る、と同じで、得られるのは固定のゲインです。2節の環境は、ゲインを選ぶ間隔を変えられるように作り、既定の1秒ごとに選び直す形で、環境が学習の流れにつながることも確かめます。その理由と、実用での扱いとの違いは、2-2節の話です。

なぜペダルではなくゲインを選ばせるのか、の説明です。ゲインを選ばせる形なら、制御の仕組み、つまり PI 制御は、人が理解できるまま残り、エージェントは、その調整だけを受け持ちます。フェーズ5-2 で人が行った調整を、エージェントに置き換える形です。ペダルを直接選ばせる形、つまりフェーズ7-1 の環境で、最終ゴールまでの道筋のフェーズ7-3 から7-5 の形との違いは、フェーズ7-1 の2-2節の、なぜペダルを直接選ばせるのか、にまとめた、とあります。

### 2-2. ゲインを選ぶ間隔

なぜ一定の間隔ごとに選び直すのか、の説明です。間隔を1秒にすると、エージェントは、走っている途中の状況、つまり目標が変わった直後か、落ち着いた後かを見て、ゲインを変えられます。間隔をエピソード全体の90秒にすれば、エピソードの始めに1組だけ選ぶ形になります。このページの2-7節と、3節以降の学習で使います。1つの環境で、両方の形を試せます。この教材では、1秒ごとに選び直す形は、環境が学習の流れにつながることを確かめるのに使います。このページの2-6節と2-8節の話です。

走行中にゲインを変えることについて、補足の囲みがあります。3つの点です。

1つ目は、一般的なことです。PI 制御のゲインは、事前に調整して、固定して使うのがふつうです。走行中に変えるのは、プラントの性質が変わる場合が多いです。たとえば、ゲインスケジューリングは、速度や負荷など、測れる運転の状態に応じて、事前に決めたゲインの表から切り替えます。適応制御は、プラントの性質の変化に合わせて、ゆっくり調整します。

2つ目は、このサンプルの扱いです。1秒ごとに選び直す形は、プラントは同じまま、場面、つまり目標が変わった直後か、落ち着いた後かに応じて、ゲインを変える形です。環境が学習の流れにつながることを確かめるためのもので、実用的な調整の形ではありません。このページの学習、つまり3節以降は、走り始めに1組だけ選ぶ形で行います。実用で、目標の変化に合わせて応答を整えたいときは、PI 制御とゲインはそのままにして、目標値に重みを掛ける2自由度の PI 制御や、目標の変化から操作の量を前もって足すフィードフォワードを使うのがふつうです。この教材では、場面に応じて出力を変える形を、学習の題材として、ペダルを直接 NN に選ばせる形、つまりフェーズ7-4 で扱います。フェーズ7-4 と7-5 のとおり、NN は PI 制御に届かない、とあります。

3つ目は、実務の目安です。走行中にゲインを切り替えるときは、切り替えたときの安定性と、出力の段差に配慮します。どの組も単独では安定でも、切り替え続けると不安定になることがあります。フェーズ5-2 の PIController は、積分の項を、K i、つまり積分のゲインを掛けた後の値で積み上げるので、K i を変えても、積分の項は跳びません。一方、K p、つまり比例のゲインを変えると、次にペダルを計算したときに、ペダルが、K p の変化かける偏差だけ跳びます。ペダルが範囲の端、つまりプラスマイナス1 で切りそろえられる場合は、それより小さくなります。

### 2-3. 行動をゲインに引き延ばす

ゲインの範囲は、kp が0 から2、ki が0 から0.5 ですが、環境が受け取る行動は、どちらもマイナス1 から1 の数にします。行動をマイナス1 から1 にそろえる理由は、フェーズ7-1 の2-3節の話です。環境の中で、次の式でゲインに引き延ばします。

式は2つです。K p イコール、a 0 に1 を足して2 で割り、2.0 を掛けたもの。K i イコール、a 1 に1 を足して2 で割り、0.5 を掛けたもの、です。

a 0 と a 1 が、行動の2つの数です。マイナス1 が下限の0、1 が上限、0 がちょうど真ん中に当たります。既定のゲイン、つまり kp 0.5、ki 0.1 は、行動では、a 0 がマイナス0.5、a 1 がマイナス0.6 になります。範囲をそろえても、環境の中で引き延ばせば、選べるゲインは制限されません。

選べる範囲を、kp 0 から2、ki 0 から0.5 にしたのは、既定のゲインの0.5 と0.1 を含み、フェーズ5-2 の4-2節で振動した、kp 5.0、ki 2.0 は含まない範囲にするためです。範囲を広げすぎると、エージェントは、意味の無い領域の試行に時間を使います。

### 2-4. 落ち着いた状態から始め、報酬は1倍にする

落ち着いた状態から始める理由です。フェーズ7-1 の環境は、フェーズ7-3 の Gazebo の環境と比べられるように、止まった状態から始めました。その場合、最初の10秒は、止まった状態から最初の目標へ加速する大きな段になり、どのエピソードにも入ります。この段では、アクセルを踏み切るしかないので、ゲインの良し悪しは、ほとんど表れません。フェーズ7-1 の5-1節の収益の内訳では、収益の約半分が、この段でした。そこで、この環境は、最初の目標の速度で落ち着いた状態、つまり速度が変わらず、ペダルが一定の状態から始めます。すべての段が、走っている途中の目標の変更になり、ゲインの差が、収益に表れやすくなります。式の環境なら、プラントの速度と力を、始めから好きな値にできます。作り方は、2-5節の reset の話です。

報酬は1倍にします。報酬は、フェーズ7-1 の2-5節の式で、10 を掛けない形にします。

式は、報酬イコール、マイナス、90分の1 かける、その1ステップの間の、e の2乗に20 かける o の2乗を足したものに、デルタ t を掛けて足し合わせたもの、です。e は誤差、o は行き過ぎ、デルタ t はプラントの刻み幅で、フェーズ7-1 の2-5節と同じ記号です。

収益と RMS の関係です。1エピソードの報酬を全部足すと、収益イコール、マイナス、誤差の2乗の平均に、20 かける 行き過ぎの2乗の平均を足したもの、になります。

平均は、どちらも90秒の平均です。落ち着いた状態から始めるので、最初の10秒は、誤差がほぼ0 です。フェーズ6-3 の RMS は、10秒からの80秒で数えます。フェーズ6-3 の2-2節の表の話です。そのため、行き過ぎが無ければ、収益は、マイナス、90分の80 かける RMS の2乗になります。実際の値での対応は、このページの2-6節で確かめます。フェーズ7-1 の環境の収益とは、報酬に掛ける数も、始め方も違うので、比べられません。

4つ目は、重みを取り違えると、どうなるかです。丸3 のゲインを、重み20 の物差しで測ると、収益はマイナス1.9537 で、既定のゲインのマイナス1.2525 よりも悪いです。報酬の値は、同じ重みの物差しの上でだけ比べられます。

5つ目は、確かめ用のシナリオ、つまり最後の列です。どの方策も、比べる20通りのシナリオより、少し悪いです。こちらのシナリオが、少し厳しいということです。重み20 の格子の最良のマイナス0.7820 と、丸2 のマイナス0.9226 の順は変わらず、差は、むしろ広がりました。格子の最良は、選ぶのに使ったシナリオにだけ合っていたわけではありません。丸2 は、確かめ用のシナリオでも、既定のゲインのマイナス1.3296 より、約31パーセントよいです。

報酬の重みと、指標での確認について、補足の囲みがあります。3つの点です。

1つ目は、一般的な考え方です。強化学習のエージェントは、報酬を大きくすることだけを目指します。重みは、追従の速さと行き過ぎのように、両立しない性質のどちらを、どれだけ優先するかを決めます。重みを変えれば、最もよい答えも変わります。

2つ目は、このページで2つの重みを比べた理由です。重みだけで、最もよいゲインと追従の様子が大きく変わることを、格子の最良とフェーズ6-3 の指標で確かめるためです。あわせて、重みによっては収益の地形が平らになり、学習がうまくいかないことも確かめました。

3つ目は、実務の目安です。重みは、学習させた結果を、報酬とは別の、人が読める数、このページではフェーズ6-3 の指標で確かめながら決めます。報酬の値を、重みの違う学習どうしで、直接比べてはいけません。この節の、重みを取り違えると、の項目のように、物差しが違うからです。

## 6. 強化学習と格子の探索を比べる

ブレーキの遅いプラントと重み20 で、2通りの格子の探索と、4-3節の丸2 の学習を比べる表があります。表は4列で、4行あります。列は、比べる項目と、2-7節の粗い格子、3-2節の細かい格子、4-3節の丸2 の SAC です。

1行目は、走らせたエピソードの数です。粗い格子は、42組かける20通りのシナリオで840、細かい格子は、255組かける20通りのシナリオで5100、SAC は1000 で、評価に、ほかに80 です。

2行目は、結果のゲインです。粗い格子は kp 0.3、ki 0.025、細かい格子は kp 0.30、ki 0.0250、SAC は kp 0.41、ki 0.026 です。

3行目は、結果の収益で、比べる20通りのシナリオの平均です。粗い格子はマイナス0.731、細かい格子はマイナス0.7312、SAC はマイナス0.8038 で、750ステップではマイナス0.7698 です。

4行目は、必要な設定です。粗い格子と細かい格子は、刻みの幅と範囲、SAC は、更新の回数などです。

読み取れることは、3つです。

1つ目は、結果の収益です。格子の探索のほうがよいです。強化学習は、格子の最良との差を、5 から10パーセントまで縮めましたが、同じにはなりませんでした。

2つ目は、エピソードの数です。この問題では、格子の探索で足ります。細かい格子は5100エピソードかかりましたが、2-7節の粗い格子は、840エピソードで、同じ最良の組にたどり着いています。選ぶ数が kp と ki の2つだけなら、粗い格子で当たりをつけ、その付近を細かく調べれば、強化学習より少ない試行で、よりよい答えが出ます。

3つ目は、かかった時間です。細かい格子と丸2 で、どちらも4分半程度でした。このページの環境ではシミュレーションが速く、強化学習の時間の多くが、NN の更新に使われています。

ゲインのように選ぶ数が2つなら、格子の探索でも、まだ扱えます。選ぶ数が増えると、格子の組の数は、急に増えます。10個の数を、それぞれ10通り試すだけで、100億通りです。こうした場合は、格子の探索の代わりに、もっと賢い探索の方法、たとえばベイズ最適化や、強化学習を使います。ベイズ最適化には、Optuna のようなライブラリがあります。

強化学習ならではの力が生きるのは、選ぶものが多い場合や、状況に応じて選び直す場合です。その最も進んだ形が、PI 制御の式そのものをやめ、観測からペダルを直接選ぶ方策、つまり NN を学ばせることです。NN の方策は、走っている途中の状況、つまり目標との差、速度、目標が変わってからの時間などに応じて、毎回違うペダルを出せます。どの状況で、どのペダルか、という対応は、表や格子では表しきれません。これは、フェーズ7-4 で扱います。ペダルを選ぶ環境はフェーズ7-1 で作り、フェーズ7-3 で、Gazebo の物理で作り直します。

課題3 です。重みを4 にして、丸2 と同じ設定で学習させます。python で train_gain.py を、マイナス2つの gradient-steps に20、マイナス2つの weight に4 を付けて実行します。5分程度かかります。途中経過は、丸1 と同じ形の4行で、return は、重み4 の報酬での収益です。1000ステップで選ぶゲインは、kp 0.51、ki 0.035 で、重み0 の丸3 の0.93 と0.167 と、重み20 の丸2 の0.41 と0.026 の間に入ります。収益は、マイナス0.6779 です。既定のゲインの重み4 での収益は、3-2節の期待する結果の2つの値から計算できます。重み0 の収益マイナス0.6265 が、誤差の2乗の分です。重み20 との差、つまりマイナス1.2525 からマイナス0.6265 を引いたマイナス0.626 を、20 で割った約0.0313 が、行き過ぎの2乗の分です。なので、マイナス、0.6265 に、4 かける0.0313 を足したもの、で、約マイナス0.752 になります。学習したゲインのマイナス0.6779 は、これより約10パーセントよいです。学習したモデルは、gain_sac_slow_brake_w4.zip に保存され、5-2節で使う2つのファイルは上書きされません。

課題4 です。既定のプラントで、丸2 と同じ設定で学習させます。python で train_gain.py を、マイナス2つの gradient-steps に20、マイナス2つの plant に default を付けて実行します。5分程度かかります。途中経過は、丸1 と同じ形の4行です。1000ステップで選ぶゲインは、kp 0.83、ki 0.156、収益はマイナス0.5437 になります。2-7節の表の、既定のプラントでの既定のゲインのマイナス0.571 より約5パーセントよく、表の最もよい組、つまり kp 0.7、ki 0.1 のマイナス0.529 に近いです。既定のプラントでは、もともと改善の余地が小さいので、学習で得られるものも小さいです。2-7節の話です。学習したモデルは、gain_sac_default_w20.zip に保存されます。

## 7. 本フェーズのまとめ

8つあります。

1つ目。ゲインを選ぶ環境は、フェーズ7-1 のペダルを選ぶ環境と、シナリオ、報酬の形、終わり方を共有します。違うのは、エージェントが選ぶもの、つまりゲイン2つ、選ぶ間隔、観測、つまり PI 制御の積分の項、始め方、つまり落ち着いた状態です。行動はマイナス1 から1 にそろえ、環境の中でゲインに引き延ばします。

2つ目。落ち着いた状態から始めるので、行き過ぎが無ければ、収益は、フェーズ6-3 の RMS の2乗かける90分の80 の、マイナスになります。

3つ目。ゲインと収益の表から、既定のプラントでは、既定のゲインが最もよい組に近いですが、ブレーキの遅いプラントでは、最もよいゲインが大きく変わり、既定のゲインの収益は、最もよい組の約1.7倍悪いことが分かりました。

4つ目。学習させる前に、格子の探索で、手で決めたゲインと最もよい組の差、つまり改善の余地を測りました。ブレーキの遅いプラントでは、重み20 なら約42パーセント、重み0 なら約3パーセントの余地がありました。

5つ目。エピソードの始めにゲインを1組選ぶ形で、SAC にゲインを学習させました。既定の設定、つまり NN の更新が1ステップに1回では、学習は正しい向きに進みますが、遅いです。1ステップに時間がかかる環境では、NN の更新の回数、gradient_steps を増やすと、同じ試行の数から多くを学べます。

6つ目。重み20 で学習したゲインは、既定のゲインより約36パーセントよく、格子の最良との差を、5 から10パーセントまで縮めました。別のシナリオでも、既定のゲインより約31パーセントよかったです。

7つ目。行き過ぎの重みを変えると、最もよいゲインが変わります。格子の最良どうしで比べると、重みを上げるほど、行き過ぎは減る代わりに、目標へ近づくのが遅くなります。重み0 のように、収益の地形が平らに近いと、学習はよい組を見つけにくいです。報酬の重みは設計の判断であり、結果は、報酬とは別の指標と、格子の探索のような基準で確かめます。

8つ目。ゲインのように選ぶ数が2つだけで、毎回同じように1組を選ぶ問題では、粗い格子から始める格子の探索で十分です。強化学習は、選ぶものが多い場合や、状況に応じて選び直す場合、つまりフェーズ7-4 の NN の方策で、力を発揮します。
