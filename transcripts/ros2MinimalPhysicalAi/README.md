# ros2MinimalPhysicalAi（聞くための原稿）

これは、ros2MinimalPhysicalAi という学習教材の、入口の案内、README の話です。

この教材は、フィジカルAI の開発に必要な技術スタックを、ROS2 の最低限の構成で一通り身に着けるためのものです。フィジカルAI とは、センサで周りを知り、判断し、モータなどを動かす AI のことです。Windows の上の WSL2 に入れた Ubuntu 24.04 と、ROS2 Jazzy を使います。

ゴールは2段階です。最初のゴールは、慣性のある車両を、目標の速度に追従させるシミュレーションを、ROS2 のノードで組み立てることで、これはフェーズ5 です。最終ゴールは、その制御を、強化学習で学習させたニューラルネットワーク、NN に置き換えて ROS2 のノードとして動かし、元の制御と同じ物差しで比べることで、これはフェーズ7-5 です。

## 全体像の絵

原文の冒頭には、教材の全体像を1枚にまとめた絵があります。アイコンや挿絵の入った、いわゆるポンチ絵です。上から順に説明します。

一番上には、「学習教材の全体像」という小さな見出しと、「ROS2 の最低限の構成で、フィジカルAI の技術スタックを一通り」という大きな題があります。

その下の大きな枠が、最初のゴールです。枠の題は「慣性のある車両を、目標の速度に追従させるシミュレーション」で、副題は「ROS2 のノードとトピックでつなぐ、閉じたループ」です。枠の中には、3つの箱が左から右へ並んでいます。1つ目は、目標速度のノード。2つ目は、PI制御のノード。3つ目は車両で、自作の疑似プラント、または Gazebo の物理です。目標速度のノードから PI制御のノードへ「目標速度」、PI制御のノードから車両へ「ペダル」の矢印があり、車両から PI制御のノードへ「速度」の矢印が戻って、閉じたループになっています。枠の右上には、速度が目標に追いつくグラフと、走る車の挿絵があります。

その下には、道のりの4つの段階が、左から右へ並んでいます。左の3つには「必須、フェーズ0 から6」、右の1つには「最終ゴールまで、フェーズ7」という見出しが付いています。

STEP 1 は、フェーズ0 から4 の「基礎」です。CLI で観察、パッケージとビルド、Pub/Sub と QoS とパラメータ、そして launch が並びます。

STEP 2 は、フェーズ5 の「制御」です。Gazebo、疑似プラント、PI制御が並び、「ここで最初のゴール」と書かれています。

STEP 3 は、フェーズ6 の「評価」です。ros2 bag で記録、ゴールの判定、そして行き過ぎ量、整定時間、RMS といった指標が並びます。

STEP 4 は、フェーズ7 の「AI」です。強化学習の環境を作る、NN の方策に置き換え、ROS2 のノードに、そして二足歩行への橋渡し、と矢印で続きます。ROS2 のノードにするところが最終ゴールで、二足歩行への橋渡しは発展です。

STEP 2 の制御からは「最初のゴールに到達」、STEP 3 の評価からは「記録して判定」という矢印が、上の最初のゴールの枠へ伸びています。

一番下には、「土台」の帯があります。4つの欄があり、実行環境は Windows 11、WSL2、Ubuntu 24.04、ROS 2 Jazzy、Gazebo。強化学習は Stable-Baselines3 で、別の仮想環境に入れます。マシンは、専用の GPU は不要。言語は、Python と C++ です。

原文は、この絵をこうまとめています。フェーズ0 から4 で基礎を固め、フェーズ5 で最初のゴールの車両シミュレーションを組み立て、フェーズ6 で記録して評価します。その先のフェーズ7 で、制御を強化学習とニューラルネットワークに置き換え、ROS2 のノードとして動かすところ、フェーズ7-5 が最終ゴールです。

各手順書では、コマンドや実行の手順の直後に、「期待する結果」として、表示の例とその読み方を書いています。そのため、ROS2 の環境を用意せずに、読み物として読むこともできます。この方針は、すべての手順書に共通です。各ページの冒頭には、そのページの表示の出どころ、つまり実際に実行して確かめた表示か、コードと仕様から想定した表示かを、「期待する結果の出どころ」として書いています。時刻、プロセスの番号、パス、数値の細部は、実行するたびに変わります。実機の表示と違う場合は、実機の表示を優先してください、とあります。

## この教材を作った理由

原文の筆者は、ROS2 の本を1冊読んだり、講座を1つ受けたりしただけでは、ROS2 を使えるようになりませんでした。振り返ってみると、つまずいた原因は、次の4つにあったと考えています。

1つ目。ROS2 はミドルウェアなので、学んだ成果が目に見えにくい。ROS2 は、プログラムどうしをつなぐための仕組みで、それ自体が何かを動かすアプリではありません。「トピックでメッセージが届いた」「ノードが一覧に出た」という練習を重ねても、自分が何を作れるようになったのかを、実感しにくいのです。

2つ目。基礎から積み上げると、実際に使う場面までの道のりが長い。通信の種類、ビルドの仕組み、launch、パラメータと順に学んでいくと、どれも大事なことではあります。しかし、それらを組み合わせて何かを動かす場面にたどり着くまでに長い時間がかかり、途中で手が止まってしまいます。

3つ目。目標を決めずに進むと、豊富なエコシステムを追いかけるうちに挫折する。ROS2 の周りには、シミュレータ、可視化のツール、自律移動やロボットアームのためのパッケージなど、たくさんの道具があります。目指すものが決まっていないと、どれも学ぶべきものに見えてきて、それらを理解しようとしているうちに、息切れしてしまいます。

4つ目。入門書は、入口を広くするほど、ゴールがぼやけやすい。入門書は、多くの読者の入口になるように、幅広い話題を少しずつ扱います。それ自体は入門書の役目ですが、1冊を読み終えたときに、何ができるようになったかが、はっきりしにくくなります。

そこでこの教材では、最初にゴールを2段階で決めました。最終ゴールは、目標の速度に追従する車両のシミュレーションを ROS2 のノードで組み立て、その制御を、強化学習で学習させた NN に置き換えて比べる、という一式です。その途中に、ROS2 だけで組み立てられる最初のゴール、フェーズ5 を置きました。

各フェーズは、この完成形に必要な部品を、1つずつ手に入れる順番に並べています。必須の範囲は、最初のゴールと、それを記録で評価するフェーズ6 までに絞りました。サービスやアクションのように、ゴールに直接使わない内容は任意にしています。周辺の道具も、Gazebo のようにゴールに使うものだけを実際に動かし、ほかはフェーズ0 で役割を紹介するだけにとどめています。

この教材は、ROS2 のすべてを網羅するものではありません。1つの完成形を作りきって、「ROS2 で何かを動かせた」という足場を作り、そこから必要に応じて、公式ドキュメントやほかの入門書で範囲を広げていくことを想定しています。

## この教材のゴール

最終ゴールのフェーズ7-5 で動かす一式は、図にまとめてあります。フェーズ0 の手順書に載っているものと同じ図で、SVG と mermaid の2つの版があります。各箱の最後の行の、色の付いた文字は、その部品を作る、または使い方を学ぶフェーズです。

まず、原文の言葉の説明です。ノード、つまり ROS2 の処理の単位どうしは、目標速度、ペダル、速度のトピックでつながります。トピックは、名前の付いた、一方向の通信の経路です。一式は、launch ファイル、つまり複数のノードをまとめて起動する設定で起動します。車両は、物理シミュレータの Gazebo の中を走ります。Gazebo との間は、ブリッジを通して、車輪のトルクとオドメトリをやり取りします。ブリッジは Gazebo の中の値と ROS2 のトピックを中継するノード、トルクは車輪を回す力、オドメトリは車両の位置と速さを表すデータです。

図の中身を、SVG の配置に沿って説明します。

図の中ほどに、大きな点線の枠があります。枠の名前は「launch ファイルで一式を起動」で、フェーズ4、5-3、5-4、7-5 が添えてあります。

枠の中の上の段には、4つの箱が左から右へ並んでいます。target_generator は、目標の速度を階段の形に送るノードで、フェーズ5-3 で作ります。nn_controller は、学習した NN でペダルを決めるノードで、フェーズ7-5 で作ります。gz_plant は、ペダルを車輪のトルクに直すノードで、フェーズ5-1 と5-4 で作ります。そして「Gazebo とブリッジ」が車両の物理を計算し、これはフェーズ5-0 と5-4 で学びます。

矢印は、target_generator から nn_controller へ「目標速度」、nn_controller から gz_plant へ「ペダル」、その逆向きに gz_plant から nn_controller へ「速度」です。さらに、gz_plant から Gazebo とブリッジへ「トルク」、その逆向きに「オドメトリ」が戻ります。

枠の中の下の段、nn_controller のすぐ下には、pi_controller の箱があります。PI制御で、引数で NN と入れ替えるもので、フェーズ5-2 で作ります。この箱には矢印がつながっていません。SVG では、nn_controller と pi_controller の2つの箱が同じ色で、ほかの箱とは色が分けてあります。

枠の上には、ROS2 の外のものが2つあります。「強化学習で学習」の箱は、Gymnasium と SB3 を使い、ROS2 の外で行うもので、フェーズ7-0 から7-4 で学びます。そこから「学習」の矢印で、「学習済みの重み」の箱につながります。重みは .npz のファイルで、numpy だけで読み、フェーズ7-4 で作ります。重みの箱からは、nn_controller へ点線の矢印が出ています。

枠の下には、記録と評価の箱があります。枠から「記録」の矢印で ros2 bag record の箱、つまりトピックをファイルに記録するフェーズ6-1 の部品へ。そこから「再生」の矢印で metrics の箱、つまり指標を計算して PI と NN を比べる、フェーズ6-3 の部品へつながります。

最初のゴールのフェーズ5 では、制御器に PI制御の pi_controller を置き、強化学習と NN の部品と、フェーズ6 で作る記録と指標の部品を除いた一式を組み立てます。PI制御は、目標との差と、その差の積み上げから、アクセルとブレーキの踏み方を決める古典的な制御です。

最終ゴールでは、pi_controller と同じトピックを受けて送る nn_controller を作り、ほかのノードのコードを変えずに、launch ファイルの引数で入れ替えます。ただし、ワールドとプラントのパラメータは、NN を学習させたときの条件に合わせます。NN の学習は、ROS2 とは別に入れる強化学習のライブラリで行い、ROS2 のノードは、書き出した重みのファイルを読むだけです。強化学習は、試した結果に点数を付け、点数が上がるように行動の決め方を学ばせる方法です。各部品で使う技術と、それを学ぶフェーズの一覧は、フェーズ0 の7節にあります。

## 対象読者

ROS2 に初めて触れる人を対象にしています。ロボット工学の予備知識は要りません。前提は、次の2つです。

1つ目は、C++ か Python のどちらかで、プログラムを書いた経験があることです。クラスを定義して使う、関数を書く、といった基本的な書き方が分かれば十分で、両方の言語の経験は要りません。手順書のサンプルは、同じ仕様のノードを Python 版と C++ 版で並べて載せているので、片方の経験があれば、もう片方もサンプルと解説を読みながら追えるように書いています。ただし、C++ を使うのはフェーズ2、3-1、4 と、フェーズ4 と5 の間に置いた任意の間章で、2つのゴールの部品、つまりフェーズ5 以降は Python で書きます。

2つ目は、Linux の基本的なコマンドを、十数個ほど使ったことがあることです。手順書では、次のようなコマンドを説明なしで使います。原文では、コマンドと、使う場面の例の2列の表になっていて、13行あります。

cd は、作業するフォルダへ移動する。

ls は、フォルダの中身を確かめる。

pwd は、今いるフォルダを確かめる。

mkdir -p は、フォルダを作る。

cat は、ファイルの中身を表示する。

mv は、ファイルを移動する、または名前を変える。

touch は、空のファイルを作る。

rm と rm -rf は、ファイルを消す、またはフォルダを中身ごと消す。学習の環境が手順書の内容とずれたときに、作ったものを消して作り直すのに使います。

nano または vim は、ターミナルの中でファイルを書き換える。どちらか一方を使えればよい。

grep は、出力やファイルから、特定の文字を含む行を探す。

source は、設定用のスクリプトを読み込む。ROS2 では頻繁に使います。

export と echo は、環境変数を設定する、また中身を確かめる。

sudo apt install は、パッケージを導入する。

rm -rf には注意書きがあります。確認なしに中身ごと消し、元に戻せません。手順書の内容と自分の環境がずれて、作り直したいときに使います。例えば、ワークスペースの生成物の build、install、log のフォルダを消してビルドし直す、作ったパッケージを消して作り直す、といった場面です。実行する前に pwd と ls で、今いる場所と消す対象を確かめます。sudo は付けません。

ほかに、ターミナルを複数開いて並べて使うこと、動き続けるコマンドを Ctrl+C で止めること、VS Code などのテキストエディタでファイルを書くことにも慣れていると、スムーズです。Linux に触れたことがない場合は、先にこれらのコマンドを一通り試してから始めてください、とあります。

手順書のサンプルコードは、GitHub のページからコピーして、自分の PC の練習環境のファイルに貼り付けて使います。touch と nano を使う方法と、VS Code を使う方法は、「サンプルコードを練習環境に置く方法」という文書にまとめてあります。そのまま貼り付けて使うことを想定しているので、コードを隅々まで暗記する必要はありません。各行が何をしているかは解説を読んで理解し、書き方そのものは、必要になったときにサンプルを見返せば足ります。

また、サンプルは、学習の要点が見えやすいように、エラー処理を最小限にしています。想定していない値、例えば時定数に0 を与えると、ノードが止まることがあります。ただ、止まるのはシミュレーションだけで、起動し直せば元に戻ります。実務のコードでは、入力の検証をもっと厚くします。その例は、フェーズ5-1 の5-1節の補足にあります。

用意するものは2つです。1つは、Windows 11 の PC で、WSL2 が使える Windows 10 でもかまいません。もう1つは、学習の時間です。所要時間は、1コマ、つまり1時間から2時間の学習のセッションを単位に書いています。

原文には、作成のときに手順を試した PC の環境の表もあります。ただし、これは必須の条件ではなく、自分の PC と比べて、ビルドの時間や GUI の動きの目安にするためのものです。この原稿では、表の中身は省きます。必要なディスクの空きの目安と、WSL2 のメモリは既定の設定のままでよいことは、環境構築の手順書に書かれています。

## 読む順番

原文では、全体の流れを、mermaid の流れ図にしています。実線の枠と矢印が、最初のゴールのフェーズ5-4 と、最終ゴールのフェーズ7-5 までの道筋で、2つのゴールは太い枠です。点線の枠は任意または発展の文書、点線の矢印は任意の道筋で、ラベルの付いたものは寄り道です。枠の先頭の番号は、後で読み上げる表の「順」と対応しています。

図の流れを、上から順に説明します。

一番上には、フェーズ0 の ROS2 の概要と、環境構築の2つが並び、どちらからもフェーズ1 の turtlesim の観察へ矢印が入ります。

フェーズ1 からフェーズ2 のワークスペースとパッケージへ、フェーズ2 からフェーズ3-1 の Publisher と Subscriber へ進みます。

フェーズ3-1 からは、矢印が3本に分かれます。フェーズ3-2a の Twist で turtlesim を動かす章、フェーズ3-2b の QoS の相性の章、そしてフェーズ5-0 の Gazebo で車両を動かす章です。また、フェーズ3-1 からは、点線で、参考資料の Node クラスの構造へも道があります。これは、いつでも読める資料です。

フェーズ3-2a と3-2b は、どちらもフェーズ3-3 のパラメータに入ります。
